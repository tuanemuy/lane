# 公開と削除

公開権限・削除権限を持つメンバーが、コンテンツの公開状態を変え、ごみ箱と完全削除を扱う。用語は `spec/requirements.md` の 1 章に、権限の名前は [index.md](index.md) の「権限」に従う。下書きの編集と保存は [content-editing.md](content-editing.md) が定める。メディアの非公開化と削除は [media.md](media.md) が定める。

## 共通の規則

[index.md](index.md) の「共通の規則」に加えて、このファイルのすべてのシナリオに適用する。各シナリオの異常系は、両方の規則に加わる分だけを書く。

- **確認した内容での確定**: [index.md](index.md) の「確認した内容での確定」に従う。確認の後の変化に当たるのは、次の表のものの変化と、確定の時点で満たさない一意な値・参照先・メディアの条件である。

  | 操作 | 確認の後に変わると、確定を拒否するもの |
  | --- | --- |
  | 公開（PUB-01、PUB-02） | 対象の下書きと公開内容、対象の置き場所（ごみ箱への移動、完全削除）、参照先の公開状態 |
  | 公開取り消し（PUB-03、PUB-04） | 対象の公開内容と下書き、対象の公開状態（先に取り消された）、対象の置き場所、対象を必須の参照または本文のリンクで参照する公開中の参照元 |
  | ごみ箱への移動（PUB-05） | 対象の公開状態、公開内容、下書き、置き場所、公開中の対象を必須の参照または本文のリンクで参照する公開中の参照元 |
  | 完全削除（PUB-07） | 対象の公開状態、公開内容、下書き、置き場所、削除の後に残る参照元、対象に加えた履歴の版 |

- **公開取り消しを含む操作**: 公開中のコンテンツのごみ箱への移動（PUB-05）と完全削除（PUB-07）は、公開取り消しを含む。PUB-03 と同じ参照の確認を行い、削除権限に加えて公開権限を必要とする。公開権限を持たないメンバーには、公開中のコンテンツのこれらの操作を示さない。複数の対象に公開中のコンテンツを含む場合、公開中の対象は条件を満たさない対象（[index.md](index.md) の「複数の対象を扱う操作」）に当たり、CMS は公開取り消しを含むため公開権限が必要であることを示す。確認の後に対象が公開された場合は、権限の不足より先に、確認の後の変更として確認を示し直す。メンバーは、公開権限を持つメンバーに公開取り消しを依頼してから操作するか、公開中の対象を外して操作し直す。
- **権限の不足**: 利用者は、権限を依頼する代わりに、示された権限を持つメンバーに操作を依頼できる。
- **公開・通知・表示反映の区別**: 操作の結果は、CMS での確定と、表示アプリへの通知の結果を分けて示す。表示アプリ上の表示反映は CMS が確認できないため、完了と示さない。通知は確定の後に行い、確定しなかった操作は通知しない。
- **操作の結果に示す通知の結果**: 操作を行ったメンバーに、CMS は、その操作の通知の宛先ごとの送信結果（送信待ち、送信成功、送信失敗）を示す。宛先は、登録の順の番号で区別して示し、宛先の URL と秘密情報は示さない。メンバーがアプリ連携の権限を持つ場合も同じである。その操作の通知が無い間、CMS は、送った通知が無いことを示し、送信成功とも送信失敗とも示さない。通知が無いのは、通知がまだ作られていない場合と、通知の宛先が登録されていない場合である。CMS は、この二つを区別せずに、どちらかであることを示す。メンバーは、結果を確かめ直せる。宛先の URL と、宛先が登録されているかどうかは、アプリ連携の権限を持つメンバーが PUB-08 と WS-09 で確かめる。
- **要件**: 5.1, 5.4, 9.1, 10.3

## PUB-01 コンテンツを公開する

- **利用者**: 公開権限を持つメンバー
- **目的**: 下書きを公開内容にし、公開取得で配信する。
- **要件**: 4.1, 4.2, 4.4, 5.1, 5.2, 5.4, 7.1, 9.1

### 正常系

1. メンバーは、下書きを持つコンテンツを開き、公開を始める。編集画面に未保存の入力がある場合、CMS は入力を下書きとして保存してから、次へ進む。
2. CMS は保存済みの下書きを検証する。検証は、入力エラーが無いこと、一意な値が他のコンテンツの公開内容と重複しないこと、参照切れ（[content-editing.md](content-editing.md) の「共通の規則」）が無いことを確かめる。参照切れは、必須の参照、任意の参照、本文のリンクのどれでも公開を妨げる。自己参照は許容する。
3. CMS は公開する内容を確認として示す。
   - 公開中のコンテンツでは、公開内容と下書きの差分。未公開のコンテンツでは、公開する下書きの内容
   - 新たに公開するメディア。本文内の画像と参照先のメディアを含む
   - 公開中のコンテンツを公開し直す場合、このコンテンツを参照している公開中の参照元。参照元の表示が変わり得ることを示す
   - 一意な値が変わる場合、変更前後の値
4. メンバーは公開を確定する。
5. CMS は下書きを公開内容にし、下書きをなくす。置き換え前の公開内容は、公開内容だった版として履歴に残す。新たに公開するメディアは、この確定に合わせて公開する。公開内容の更新日時は確定の日時になる。
6. CMS は公開が確定したことを示す。コンテンツは公開中で、下書きを持たない。
7. CMS は表示アプリへ通知する。未公開だったコンテンツは公開として、公開中だったコンテンツは更新として伝える。CMS は通知の結果を、公開の確定と分けて示す。通知の失敗は PUB-08 が扱う。

### 異常系

- **入力エラー**: 下書きに入力エラーがある場合、CMS は公開せず、該当する項目と修正理由を示す。メンバーは EDIT-03 で直して保存し、公開し直す。公開内容が現行の制約を満たさないコンテンツを編集した下書きも、違反を解消するまで公開しない。
- **一意な値の重複**: 一意な値が他のコンテンツの公開内容と重複する場合、CMS は公開せず、項目と相手のコンテンツを示す。メンバーは、値を変えて保存するか、相手の公開を取り消してから公開する。二人が同じ値を同時に公開した場合、先に確定した一方だけが公開され、他方はこのエラーになる。
- **参照先が公開されていない**: 下書きが参照切れを持つ場合、CMS は公開せず、該当する項目と参照先を示す。メンバーは、参照先を先に公開する、示された参照先をその場で対象に加えて同時に公開する、または参照を外すか選び直して保存する。参照先を対象に加えた公開は、PUB-02 の確認から続ける。
- **未保存の入力の保存ができない**: 公開を始めたときの未保存の入力の保存が競合または失敗した場合、CMS は公開を始めない。保存できない入力と保存の失敗は EDIT-03、競合は EDIT-10 の扱いになる。メンバーは保存を終えてから公開し直す。
- **非推奨のモデル**: 非推奨のモデルのコンテンツには、公開の操作を示さない（EDIT-16）。
- **下書きが無い**: 下書きも未保存の入力も持たないコンテンツには、公開の操作を示さない。
- **権限不足（公開）**: 共通の規則に従う。公開権限を持たず編集権限を持つメンバーは、下書きを保存し、公開権限を持つメンバーに公開を依頼する。
- **権限不足（メディア公開）**: 新たに公開するメディアがあり、メンバーがメディア公開権限を持たない場合、CMS は公開せず、該当するメディアと必要な権限を示す。メディアは非公開のままとする。メンバーは、公開権限とメディア公開権限を持つメンバーに公開を依頼する。
- **新たに公開するメディアの上限**: 一つの操作で新たに公開するメディアの数が上限（[index.md](index.md) の「複数の対象を扱う操作」）を超える場合、CMS は公開せず、上限を示す。この下書きは、一つの操作で公開できない。メンバーは、新たに公開するメディアが上限の中に収まるように下書きを直して保存し、公開し直す。
- **確定の失敗**: 確定が失敗した場合、公開内容、下書き、メディアの公開範囲は変わらない。CMS は失敗の理由を示す。メンバーは公開し直す。
- **操作の取り消し**: 確認でやめても、確認の前に保存した下書きは残る。公開した後に配信をやめる場合は、PUB-03 で公開を取り消す。公開の前の公開内容に戻す場合は、EDIT-14 で履歴の版を下書きとして復元し、公開し直す。公開したメディアは、公開を取り消しても自動で非公開にならない（MEDIA-07）。

## PUB-02 複数のコンテンツを一括公開する

- **利用者**: 公開権限を持つメンバー
- **目的**: 複数の下書きを、一つの操作で同時に公開する。
- **要件**: 4.2, 4.4, 5.1, 5.2, 5.4, 9.1

### 正常系

1. メンバーは、モデルの一覧（EDIT-01）で下書きを持つコンテンツを一件以上選び、一括公開を始める。
2. CMS はすべての対象を検証する。検証の内容は PUB-01 と同じ。同じ操作で公開する対象は、参照先として公開済みと扱う。互いを必須参照するコンテンツは、同じ操作で公開できる。対象外の参照先には、現在の公開内容を使う。
3. CMS は確認を示す。対象の一覧、対象ごとの公開内容との差分、新たに公開するメディア、対象を参照している公開中の参照元を示す。
   - メンバーは確認の中で、ほかのモデルの下書きを持つコンテンツを検索して対象に加えられる。対象から外すこともできる。
   - 対象を変えるたびに、CMS はすべての対象を検証し直し、確認を示し直す。
4. メンバーは公開を確定する。
5. CMS はすべての対象を同時に公開する。対象ごとの結果は PUB-01 と同じ。
6. CMS は表示アプリへ、変更した対象を識別できる一つの通知で伝える。対象ごとに公開か更新かを識別できる。

### 異常系

- **一部の対象の検証エラー**: 扱いは、[index.md](index.md) の「複数の対象を扱う操作」に従う。CMS は、該当する対象ごとに、項目と理由を示す。対象から外すことで別の対象の参照先が公開されなくなる場合、その対象もエラーになる。
- **公開対象に含まれない参照先**: 対象が参照切れを持ち、その参照先が対象に含まれない場合、CMS は該当する対象、項目、参照先を示す。参照先が下書きを持つ通常の管理対象のコンテンツであれば、メンバーはその場で参照先を対象に加えられる。モデルが異なる参照先も加えられる。加えた参照先も検証の対象になる。ごみ箱にある参照先は加えられない。メンバーは、PUB-06 で復元してから加えるか、参照を外して保存する。
- **対象間の一意な値の重複**: 対象どうしで一意な値が重複する対象は、条件を満たさない対象に当たる。
- **対象の上限**: 対象を分けて操作する場合、互いに参照し合う対象は、同じ操作に含める。互いを必須の参照で参照し合う対象が上限を超える場合は、一つの操作で公開できない。メンバーは、参照し合う対象が上限の中に収まるように参照を直して保存し、公開し直す。新たに公開するメディアの数が上限を超える場合も、対象を分けて公開する。
- **対象に選べないもの**: 下書きを持たないコンテンツ、ごみ箱のコンテンツ、非推奨のモデルのコンテンツは、対象に選べない。
- **権限不足**: 公開権限の不足は共通の規則に従う。新たに公開するメディアがあり、メディア公開権限を持たない場合、CMS は該当するメディアと必要な権限を示す。
- **確定の失敗**: 確定が失敗した場合、どの対象も公開されず、メディアは非公開のままとする。通知は行わない。
- **操作の取り消し**: 公開した後に取り消す場合は、PUB-04 で対象の公開を取り消す。

## PUB-03 公開を取り消す

- **利用者**: 公開権限を持つメンバー
- **目的**: コンテンツの配信をやめ、内容を下書きとして残す。
- **要件**: 4.2, 4.4, 5.2, 5.4, 6.4, 7.1, 9.1

### 正常系

1. メンバーは、公開中のコンテンツを開き、公開取り消しを始める。
2. CMS は、他のコンテンツの公開内容からの参照を確かめる。必須の参照と本文のリンクで参照されていないことを確かめる。
3. CMS は確認を示す。
   - 公開取得で返さなくなること
   - 最新の内容が下書きとして残り、編集を続けられること
   - 任意の参照だけで参照している公開中の参照元。参照元の取得では、この参照を未設定として返すことを示す
   - 下書きから参照しているコンテンツ。参照切れになることを示す
   - 使用しているメディアが公開のまま残ること
4. メンバーは取り消しを確定する。
5. CMS は公開内容をなくす。コンテンツは未公開になる。
   - 下書きがあった場合、下書きはそのまま残り、公開内容は公開内容だった版として履歴に残る。
   - 下書きが無かった場合、公開内容が下書きになる。
6. CMS は表示アプリへ公開取り消しとして伝える。通知の結果は、取り消しの確定と分けて示す。
7. 参照元の公開内容は変わらない。参照元の編集画面は参照切れを示す。このコンテンツを再び公開すると、参照元を公開し直さなくても、取得は参照を返す。

### 異常系

- **必須の参照がある**: 他のコンテンツの公開内容から必須の参照または本文のリンクで参照されている場合、CMS は取り消さない。参照元のコンテンツと項目を示し、解消方法を示す。メンバーは次のいずれかを行ってから取り消す。
  - 参照元の下書きから参照を除いて公開する
  - 参照元の公開を先に取り消す
  - 示された参照元をその場で対象に加えて、同時に取り消す。参照元を対象に加えた取り消しは、PUB-04 の確認から続ける
- **権限不足**: 共通の規則に従う。参照元の下書きの修正は編集権限を、参照元の公開と公開取り消しは公開権限を必要とする。
- **リソース不在**: 未公開のコンテンツには、公開取り消しの操作を示さない。
- **操作の取り消し**: 取り消した後に配信を戻す場合は、PUB-01 で公開し直す。下書きがあった場合、公開していた内容は履歴に残る。同じ内容を公開するには、EDIT-14 でその版を復元してから公開する。使用していたメディアを非公開にする場合は MEDIA-07 で行う。

## PUB-04 複数のコンテンツの公開を取り消す

- **利用者**: 公開権限を持つメンバー
- **目的**: 互いに参照し合うコンテンツを含む複数のコンテンツの配信を、一つの操作でやめる。
- **要件**: 4.2, 5.1, 5.2, 5.4, 9.1

### 正常系

1. メンバーは、モデルの一覧（EDIT-01）で公開中のコンテンツを一件以上選び、公開取り消しを始める。
2. CMS はすべての対象の参照を確かめる。同時に取り消す対象間の参照は許容する。操作の後も公開を続けるコンテンツから、必須の参照と本文のリンクで参照されている対象が無いことを確かめる。
3. CMS は確認を示す。対象の一覧と、対象ごとに PUB-03 と同じ内容を示す。
   - メンバーは確認の中で、ほかのモデルの公開中のコンテンツを検索して対象に加えられる。対象から外すこともできる。
   - 対象を変えるたびに、CMS はすべての対象の参照を確かめ直し、確認を示し直す。
4. メンバーは取り消しを確定する。
5. CMS はすべての対象の公開を同時に取り消す。対象ごとの結果は PUB-03 と同じ。
6. CMS は表示アプリへ、変更した対象を識別できる一つの通知で、公開取り消しとして伝える。

### 異常系

- **公開を続ける対象からの必須の参照**: 対象外の公開中のコンテンツから必須の参照または本文のリンクで参照されている対象は、条件を満たさない対象に当たる。CMS は、該当する対象ごとに参照元と項目を示す。メンバーは、示された参照元をその場で対象に加えるか、参照元から参照を除いて公開してから、取り消し直す。モデルが異なる参照元も加えられる。加えた参照元も参照の確認の対象になる。
- **対象の上限**: 対象を分けて操作する場合、対象外の公開中のコンテンツから必須の参照を受ける対象は、参照元を先に操作する。
- **対象に選べないもの**: 未公開のコンテンツとごみ箱のコンテンツは、対象に選べない。
- **権限不足**: 共通の規則に従う。
- **操作の取り消し**: 取り消した後に配信を戻す場合は、PUB-02 で対象を一括公開する。

## PUB-05 コンテンツをごみ箱へ移動する（複数対象を含む）

- **利用者**: 削除権限を持つメンバー
- **目的**: コンテンツを通常の管理対象から外し、ごみ箱に保持する。非推奨のモデルのコンテンツを除き、復元できる。
- **要件**: 4.2, 4.3, 5.2, 5.4, 6.4, 7.2, 9.1

### 正常系（未公開のコンテンツ）

1. メンバーは、一覧または編集画面から、未公開のコンテンツの削除を始める。
2. CMS は確認を示す。ごみ箱へ移動すること、PUB-06 で復元できること、ごみ箱の保持方針による自動整理で完全削除される時期、このコンテンツを下書きから参照しているコンテンツを示す。非推奨のモデルのコンテンツでは、復元できることの代わりに、通常の管理対象へ戻せないことを示す。
3. メンバーは削除を確定する。
4. CMS はコンテンツをごみ箱へ移動する。移動時点の下書きと履歴を保持する。コンテンツは、通常の一覧、参照先の候補、プレビュー取得、通常の編集の対象から外れる。
5. このコンテンツを参照している下書きは、編集画面で参照切れを示す。

### 正常系（公開中のコンテンツ）

1. メンバーは、公開中のコンテンツの削除を始める。
2. CMS は、PUB-03 と同じ参照の確認を行う（「共通の規則」の「公開取り消しを含む操作」）。
3. CMS は確認を示す。未公開のコンテンツの確認に加えて、この削除が公開取り消しを含むことと、PUB-03 の確認の内容を示す。
4. メンバーは削除を確定する。
5. CMS は公開を取り消し、コンテンツをごみ箱へ移動する。ごみ箱のコンテンツは未公開で、最新の内容を下書きとして保持する。下書きがあった場合、公開内容は履歴に残る。
6. CMS は表示アプリへ公開取り消しとして伝える。

### 正常系（複数のコンテンツ）

1. メンバーは、モデルの一覧（EDIT-01）でコンテンツを一件以上選び、削除を始める。未公開のコンテンツと公開中のコンテンツを同時に選べる。
2. CMS はすべての対象の参照を確かめる。同時に移動する対象間の参照は許容する。操作の後も公開を続けるコンテンツから、公開中の対象が必須の参照と本文のリンクで参照されていないことを確かめる。
3. CMS は確認を示す。対象の一覧と、対象ごとに単独の移動と同じ内容を示す。
   - メンバーは確認の中で、ほかのモデルのコンテンツを検索して対象に加えられる。対象から外すこともできる。
   - 対象を変えるたびに、CMS はすべての対象の参照を確かめ直し、確認を示し直す。
4. メンバーは削除を確定する。
5. CMS はすべての対象を同時にごみ箱へ移動する。対象ごとの結果は単独の移動と同じ。
6. CMS は表示アプリへ、公開中だった対象を識別できる一つの通知で、公開取り消しとして伝える。公開中だった対象が無ければ通知しない。

### 異常系

- **必須の参照がある**: 公開中の対象が、操作の後も公開を続けるコンテンツから必須の参照または本文のリンクで参照されている場合、その対象は条件を満たさない対象に当たる。示す内容と解消方法は、単独の移動では PUB-03 の「必須の参照がある」、複数の対象では PUB-04 の「公開を続ける対象からの必須の参照」と同じである。示された参照元をその場で対象に加えた移動は、複数のコンテンツの確認から続ける。下書きからの参照と任意の参照は、移動を妨げない。
- **未保存の入力**: 編集画面に未保存の入力がある場合、CMS は、その入力がごみ箱の内容に含まれないことを確認とあわせて示す。メンバーは、先に保存するか、そのまま削除する。
- **権限不足（削除）**: 共通の規則に従う。
- **非推奨のモデルのコンテンツ**: 非推奨のモデルのコンテンツは、ごみ箱へ移動すると通常の管理対象へ戻せない（EDIT-16）。CMS は確認で、復元できないことを示す。複数の対象では、該当する対象ごとに示す。メンバーは、戻せないことを確かめて削除を確定する。
- **操作の取り消し**: 移動した後に戻す場合は、PUB-06 で復元する。復元は未公開として戻すため、配信を戻すには PUB-01 または PUB-02 で公開し直す。非推奨のモデルのコンテンツの移動は、取り消せない。

## PUB-06 ごみ箱のコンテンツを確認し、復元する

- **利用者**: 削除権限を持つメンバー
- **目的**: ごみ箱のコンテンツを確かめ、通常の管理対象へ戻す。
- **要件**: 4.2, 4.3, 5.2, 6.3, 7.2

### 正常系

1. メンバーはごみ箱の一覧を開く。CMS は、ごみ箱のコンテンツを通常の一覧と分けて示す。メンバーは、モデルで絞り込める。コンテンツごとに、モデル、一覧表示用の項目の値、移動した日時と実行者、保持方針による自動整理で完全削除される時期を示す。
2. メンバーはコンテンツを選び、移動時点の下書きと履歴を読み取り専用で確認する。ごみ箱にある間に移行または値の書き換えで変わった内容は、変わった後の内容を示す。
3. メンバーは、ごみ箱の一覧から、またはごみ箱のコンテンツの内容を確認している場面からそのまま、復元する。復元は、確認を挟まず、一つの操作で確定する。
4. CMS はコンテンツを通常の管理対象へ戻し、未公開として戻したことと、公開していないことを示す。コンテンツは未公開で、下書きと履歴を持つ。コンテンツID は変わらない。表示アプリへは通知しない。
5. 編集画面は、復元した下書きの入力エラー、参照切れ、一意な値の他のコンテンツの公開内容との重複を示す。
6. 配信を戻す場合、メンバーは必要な修正を保存し、PUB-01 で公開する。

### 異常系

- **復元した下書きの問題**: ごみ箱にある間に、スキーマの反映で検証を満たさなくなった、参照先が公開を取り消された、同じ一意な値を他のコンテンツが公開した場合も、復元は行う。問題は下書きの入力エラー、参照切れ、重複として示し、公開の前に解消する。
- **ごみ箱にある間の内容の変化**: メンバーがごみ箱の一覧または内容を開いた後に、移行または値の書き換えで内容が変わっていた場合も、復元は行う。復元は、復元の時点の内容を戻す。編集画面は、変わった後の内容を示す。
- **権限不足**: どのメンバーも、ごみ箱の一覧と内容を確認できる。復元の操作の扱いは、共通の規則に従う。
- **単一モデルの二つ目**: 通常の管理対象に既にコンテンツがある単一モデルのコンテンツの復元を、CMS は拒否し、既にあることを示す（EDIT-04 の「二つ目のコンテンツ」）。
- **非推奨のモデルのコンテンツ**: 非推奨のモデルのコンテンツには、復元の操作を示さない（EDIT-16）。内容と履歴の確認と、完全削除（PUB-07）は行える。
- **リソース不在**: 復元の時点で、保持方針による自動整理または他のメンバーの操作で完全削除されていた場合、CMS は復元せず、存在しないことを示す。完全削除したコンテンツは復元できない。他のメンバーが先に復元していた場合、CMS は通常の管理対象にあることを示す。モデルがスキーマの反映で削除された場合、そのモデルのコンテンツはごみ箱に現れない。
- **操作の取り消し**: 復元した後に戻す場合は、PUB-05 でごみ箱へ移動する。

## PUB-07 コンテンツを完全削除する

- **利用者**: 削除権限を持つメンバー
- **目的**: コンテンツを、履歴を含めて復元できない形で削除する。
- **要件**: 4.2, 4.3, 5.2, 5.4, 7.2, 8.1, 9.1

### 正常系

1. メンバーは、ごみ箱の一覧またはモデルの一覧（EDIT-01）で、一件以上のコンテンツを明示して選び、完全削除を始める。ごみ箱のコンテンツの内容を確認している場面（PUB-06）と、単一モデルのコンテンツの編集画面（EDIT-04）からは、そのコンテンツを対象にして、そのまま始められる。
2. CMS はすべての対象の削除条件を確かめる。
   - 削除の後に残るコンテンツの公開内容、下書き、保持対象の履歴、ごみ箱のコンテンツから、必須の参照または本文のリンクで参照されていないこと
   - 同じ操作で削除する対象間の参照は許容する
   - 対象に公開中のコンテンツを含む場合、PUB-03 と同じ参照の確認（「共通の規則」の「公開取り消しを含む操作」）
3. CMS は確認を示す。
   - 対象の一覧と、履歴を含めて削除し、復元できないこと
   - 公開中の対象について、この削除が公開取り消しを含むこと
   - 任意の参照だけで参照している参照元。参照が未設定になることを示す
   - 使用しているメディアとほかのコンテンツは削除しないこと
   - バックアップには取得時点の内容が残り得ること。CMS の通常データと区別して示す
   - メンバーは確認の中で、ほかのモデルのコンテンツと、ごみ箱・通常の管理対象のもう一方にあるコンテンツを検索して対象に加えられる。対象から外すこともできる。対象は一件ずつ明示して加える
   - 削除の後に残るコンテンツの履歴の版が削除を妨げている場合、CMS は確認の中でその版を示す。メンバーは、その版を一件ずつ明示して対象に加えられる。対象から外すこともできる。対象に加えた版について、CMS は EDIT-17 の確認と同じ内容を示す
   - 対象を変えるたびに、CMS はすべての対象の削除条件を確かめ直し、確認を示し直す
4. メンバーは、復元できないことを確かめて、完全削除を確定する。
5. CMS はすべての対象を、公開内容、下書き、履歴とともに同時に削除する。対象に加えた履歴の版も、同じ確定で削除する。版を削除したコンテンツの公開内容、下書き、ほかの版は変えない。対象は、一覧、検索、ごみ箱、参照先の候補に現れない。
6. 公開中だった対象は、表示アプリへ公開取り消しとして伝える。複数の対象は一つの通知で伝える。
7. フォームの回答が問い合わせ対象として持つ送信時の情報は、変わらない。回答は完全削除を妨げない。

### 異常系

- **非推奨のモデルのコンテンツ**: 非推奨のモデルのコンテンツも、ほかのコンテンツと同じ規則で完全削除できる。ごみ箱からの復元は行えない（EDIT-16）。
- **必要な参照が残る**: 削除の後に残る対象から必須の参照または本文のリンクで参照されている対象は、条件を満たさない対象に当たる。CMS は、該当する対象ごとに、参照元、参照している内容の種類（公開内容・下書き・履歴の版）、参照元の置き場所（通常・ごみ箱）、解消方法を示す。メンバーは次のいずれかを行ってから削除し直す。
  - 参照元の公開内容からの参照は、参照元の下書きから参照を除いて公開する、または参照元の公開を取り消す
  - 参照元の下書きからの参照は、参照元の下書きから参照を除いて保存する
  - 参照元の履歴の版からの参照は、示された版をその場で対象に加える。削除するのはその版だけで、参照元のコンテンツは残る
  - ごみ箱の参照元からの参照は、示された参照元をその場で対象に加える
  - 参照元を残す必要が無い場合は、示された参照元をその場で対象に加える。モデルが異なる参照元も加えられる。加えた参照元も削除条件の確認の対象になる
- **解消に必要な権限**: 参照元の下書きの修正は編集権限、参照元の公開と公開取り消しは公開権限、参照元の履歴の版の削除と参照元の完全削除は削除権限を必要とする。CMS は参照を自動で解消せず、無関係なコンテンツと履歴を連鎖して削除しない。削除する履歴の版は、メンバーが明示して対象に加えたものに限る。
- **権限不足（削除）**: 共通の規則に従う。
- **操作の取り消し**: 確定した完全削除は取り消せない。

## PUB-08 表示アプリへの通知の状況を確認し、失敗した通知を再試行する（複数の通知を含む）

- **利用者**: アプリ連携の権限を持つメンバー
- **目的**: 公開内容の変更が表示アプリへ伝わったかを確かめ、伝わっていない通知を送り直す。
- **要件**: 4.1, 5.2, 5.4

未対処と対処済みの規則、未対処の件数の数え方、送信結果、自動の再試行の回数、手動再試行の規則、再試行を始めた組と再び送信失敗になった組の扱いは、[index.md](index.md) の「未対処の失敗」に従う。

### 正常系

1. CMS は、[index.md](index.md) の「未対処の失敗」のとおり、表示アプリへの通知の未対処の失敗を示す。
2. メンバーは通知の状況を開く。通知は、作られた時点で登録されている宛先（WS-09）ごとに送信結果を持つ。CMS は、通知と宛先の組を、通知の新しい順に一覧する。組ごとに次を示す。
   - 通知の種別と確定した日時。スキーマの反映による通知の種別は、スキーマの反映である。スキーマの反映は、移行の適用と直接反映を含む。コンテンツの操作による通知の種別は、その通知が含む変更の種類（公開、更新、公開取り消し。APP-11）のすべてである
   - 変更した対象のコンテンツ。一つの操作で確定した複数の変更は、変更したすべての対象を列挙した一つの通知である
   - スキーマの反映による通知では、スキーマの版
   - 参照元への影響。変更した対象を参照している公開中のコンテンツ
   - 宛先、送信結果、送信した日時、失敗の理由
3. 送信失敗の組には、未対処か対処済みかを示す。
4. CMS は、送信成功が宛先による通知の受け取りを示し、表示アプリ上の表示反映を示さないことを示す。
5. メンバーは、一覧を未対処で絞り込み、送信失敗の組の失敗の理由を確認する。
6. 原因が宛先または秘密情報の設定にある場合、メンバーは宛先の設定を直す（WS-09）。
7. メンバーは、送信失敗の組を一件以上選び、一度に再試行する。宛先が止まっていた間に失敗した複数の通知を、一つの操作で送り直せる。送り直し方は、[index.md](index.md) の「未対処の失敗」の手動再試行に従う。通知は、通知を識別する情報と、変更の順序を判別する情報を持つ（APP-11）。表示アプリは、重複して届いた通知を通知を識別する情報で、到着順が入れ替わった通知を変更の順序を判別する情報で見分けられる。
8. CMS は、組ごとの再試行の結果を示す。送信の結果は組ごとに決まり、ある組の失敗はほかの組の結果を変えない。

### 異常系

- **再試行の失敗**: 再試行が失敗した組には、CMS は新しい失敗の理由を示す。原因が宛先または秘密情報の設定にある場合、メンバーは設定を直してから再試行する（WS-09）。原因が表示アプリにある場合、メンバーは開発者に連絡する。
- **再試行しない失敗**: 表示アプリが別の手段で更新済みで、再試行が不要な場合、メンバーは、送信失敗の組を一件以上選び、一度に対処済みとして記録する。
- **対象に選べない組**: 送信待ちと送信成功の組は、再試行にも対処済みの記録にも選べない。同じ組の再試行が重なって届いても、表示アプリは通知を識別する情報で重複を見分けられる。
- **選んだ後の変化**: 対処済みの記録を確定するまでに、選んだ組のいずれかで再試行が始まっていた場合（[index.md](index.md) の「未対処の失敗」の表）と、再試行を確定するまでに、選んだ組の宛先が削除された場合、その組は、[index.md](index.md) の「複数の対象を扱う操作」の、条件を満たさない対象に当たる。再試行を確定するまでに再試行が先に始まっていた組の扱いは、[index.md](index.md) の「未対処の失敗」の表に従う。同じ操作を誤って繰り返した場合と、ほかのメンバーが先に再試行した場合が当たる。
- **通知の対象にならない操作**: 下書きの保存と破棄、下書きだけの値の書き換え、確定しなかった操作、失敗した移行は通知しないため、一覧に現れない。通知は非公開の内容を含まない。
- **通知設定が無い**: 通知の宛先の決まり方は、WS-09 の手順 3 に従う。宛先が無いワークスペースでは、通知を送らず、失敗も生じない。CMS は宛先が無いことを示す。
- **権限不足**: 共通の規則に従う。公開内容を変える操作を管理画面で行ったメンバーは、その操作の結果で、自分の操作の通知の結果を確認できる（PUB-01）。スクリプトからの操作の結果は、通知の結果を含まない（APP-09）。
- **リソース不在**: 通知の対象のコンテンツがその後に完全削除されていても、通知は一覧に残り、再試行できる。対象はコンテンツID で示す。宛先が WS-09 で削除されている組は、宛先の URL を示さず、削除済みの宛先であることを示す。その組は再試行に選べない。メンバーはその組を対処済みとして記録する。
- **操作の取り消し**: 送った通知は取り消せない。対処済みの記録の扱いは、[index.md](index.md) の「未対処の失敗」に従う。
