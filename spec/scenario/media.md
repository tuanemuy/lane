# メディア

編集権限を持つメンバーが、メディアを登録して再利用し、説明を編集する。メディア公開権限を持つメンバーが、メディアの非公開化と公開のメディアの削除を扱う。権限の名前と行える操作は `spec/scenario/index.md` の「権限」に従う。用語は `spec/requirements.md` の 1 章に従う。

## 共通の規則

`spec/scenario/index.md` の「共通の規則」に加えて、このカテゴリーに次を適用する。

メディアは、非公開または公開のいずれかである。この別を、メディアの公開範囲と呼ぶ。登録したメディアは非公開である。メディアは、それを使用するコンテンツの公開と、公開内容の値の書き換えの確定に合わせて公開される。移行は、内容が使っていないメディアを加えないので、新たに公開するメディアを生じない。下書きの保存、下書きの値の書き換え、プレビューでは公開されない。コンテンツの公開時に使用メディアの公開範囲を確認する流れは、PUB-01 と PUB-02 が定める。

CMS が管理する配信は、CMS の配信の入口を指す。入口は、要求のたびにメディアの公開範囲と、要求が示す資格を確かめる。資格は、メンバーのセッション、またはプレビュー用の配信先である。プレビュー用の配信先は、プレビュー取得の結果が非公開のメディアに返す、有効期間を限った配信先を指す（APP-05）。入口は、資格を示さない要求には、公開のメディアの内容だけを返す。非公開のメディアの内容は、資格を示す要求にだけ返す。非公開化（MEDIA-07）の確定の後、入口は、そのメディアの元の画像と派生形式への、資格を示さない要求を、すべて拒否する。削除（MEDIA-08）の確定の後は、資格を示す要求も拒否する。CMS は、配信した内容を保持しない。メディアの実体は登録後に変わらないので、CMS は、公開のメディアの応答で、長く保持してよいことを示す。長く保持するのは、入口の先の、表示アプリ、その CDN、ブラウザである。入口の先に残った内容と、外部が保存・複製した内容を、CMS は回収しない。

メディアの使用箇所は、メディアを使っている内容ごとに一件である。使用箇所は、内容の種類（公開内容、下書き、履歴の版）と、その内容を持つコンテンツの置き場所（通常、ごみ箱）の二つで表す。ごみ箱のコンテンツは公開内容を持たないので、ごみ箱の使用箇所の内容の種類は、下書きまたは履歴の版である。公開内容での使用箇所を公開使用と呼ぶ。

## MEDIA-01 メディアを登録する

- **利用者**: 編集権限を持つメンバー
- **目的**: メンバーが、コンテンツで使うファイルをワークスペースのメディアとして登録する
- **要件**: 4.4, 10.4

### 正常系

1. メンバーは、メディアの管理でファイルを選び、登録する
2. CMS は、ファイルが対応形式と容量の上限を満たすことを確かめる。対応形式は JPEG、PNG、WebP、AVIF、PDF である。容量の上限は APP-12 が定める。管理画面とトークンのどちらの経路の登録にも、同じ対応形式と上限を適用する
3. CMS は、形式、容量、画像の幅・高さを記録し、ファイルを非公開のメディアとして登録する。管理用の名称には、元のファイル名が入る
4. メンバーは、登録したメディアが一覧に加わり、非公開であることを確認する
5. 画像のメディアでは、スキーマで定義した派生形式の生成が始まる。画像でないメディアには、派生形式を生成しない。メンバーは、生成状況を確認できる（MEDIA-10）
6. メンバーは、管理用の名称と説明を整える（MEDIA-04）。コンテンツでは、登録したメディアを選んで使う（MEDIA-03）
7. 登録しただけでは、メディアは公開されない。メディアを使用するコンテンツを公開したとき、公開の確定に合わせて公開される（PUB-01）

### 異常系

- **入力エラー**: 対応形式でないファイルと、容量の上限を超えるファイルは、登録を拒否される。CMS は、拒否の理由、対応形式、容量の上限を示す。メンバーは、ファイルを対応形式に変えるか、容量を減らして登録し直す
- **保存容量の不足**: 設置の保存容量が足りず登録できない場合、CMS は、登録できなかったことと理由を示す。メンバーは、ホスティング運営者に容量の確保を依頼する
- **通信断**: 送信の途中で通信が途切れたファイルは登録されない。メンバーは、再接続の後に登録し直す
- **操作の取り消し**: 送信の途中で登録をやめると、メディアは登録されない。登録を終えたメディアを取りやめる場合は、削除する（MEDIA-08）

## MEDIA-02 メディアの項目・本文へのドロップ・貼り付けでメディアを登録して挿入する

- **利用者**: 編集権限を持つメンバー
- **目的**: メンバーが、編集の流れを離れずに、手元の画像をコンテンツに入れる
- **要件**: 4.3, 4.4, 6.4

### 正常系

1. メンバーは、コンテンツの編集画面で、メディアの項目または本文へ、ファイルをドロップするか貼り付ける。メディアの項目は、どの対応形式のファイルも受け付ける。本文は、画像のファイルだけを受け付ける
2. CMS は、ファイルを MEDIA-01 と同じ確認を経て、非公開のメディアとして登録する
3. CMS は、登録したメディアを、ドロップした項目、または本文の入力位置に挿入する
4. メンバーは、挿入した画像の代替テキストを入力する（MEDIA-05）
5. メンバーは、下書きを保存する。保存した下書きは、そのメディアの使用箇所になる。保存しても、メディアは公開されない
6. 登録したメディアは、メディアの管理にも現れる。ほかのコンテンツでも再利用できる（MEDIA-03）

### 異常系

- **入力エラー**: 対応形式でないファイル、容量の上限を超えるファイル、本文へ入れた画像でないファイルは、登録も挿入もされない。CMS は、拒否の理由、対応形式、容量の上限を示す。編集中のほかの入力は編集画面に残る。メンバーは、ファイルを直してドロップし直す
- **非推奨の項目**: 非推奨の項目は読み取り専用であり、ドロップと貼り付けを受け付けない
- **通信断**: 通信が途切れて登録できなかったファイルは挿入されない。編集中のほかの入力は編集画面に残る。メンバーは、再接続の後にドロップし直す
- **操作の取り消し**: 挿入した画像を項目や本文から取り除いた場合と、下書きを保存せずに編集画面を離れた場合、登録したメディアは非公開のまま、使用箇所のないメディアとして残る。メンバーは、残ったメディアを再利用するか（MEDIA-03）、削除する（MEDIA-08）

## MEDIA-03 登録済みのメディアを検索・選択して再利用する

- **利用者**: 編集権限を持つメンバー
- **目的**: メンバーが、登録済みのメディアを探して、コンテンツで使う
- **要件**: 4.4

### 正常系

1. メンバーは、コンテンツの編集画面で、メディアの項目、または本文の画像を入れる位置から、登録済みのメディアを選ぶ操作を始める
2. メンバーは、管理用の名称と検索情報の部分一致でメディアを検索する
3. CMS は、候補ごとに、縮小した表示、管理用の名称、形式、画像の幅・高さ、公開範囲を示す
4. メンバーは、メディアを選ぶ。CMS は、選んだメディアを項目または本文に挿入する
5. CMS は、メディアの共有する説明を、挿入した使用箇所の説明に写す。メンバーは、使用箇所に合わせて説明を直す（MEDIA-05）
6. メンバーは、下書きを保存する。同じメディアを、複数のコンテンツと複数の項目で使える
7. メンバーは、メディアの管理でも同じ検索を行い、登録済みのメディアを確認する

### 異常系

- **入力エラー**: メディアの項目には、どの対応形式のメディアも選べる。本文の画像には、画像でないメディアを選べない。CMS は、選べない候補とその理由を示す。メンバーは、画像のメディアを選ぶ
- **リソース不在（検索）**: 検索に該当するメディアがない場合は、`spec/scenario/index.md` の「一覧の絞り込み」の該当なしになる。メンバーは、検索の語を変えるか、新しく登録する（MEDIA-01、MEDIA-02）
- **リソース不在（削除済み）**: 選んだメディアが下書きの保存までに削除された場合、CMS は、そのメディアが存在しないことを項目とともに示す。メンバーは、別のメディアを選び直して保存する
- **操作の取り消し**: メンバーがメディアを選ばずに操作をやめると、項目と本文は変わらない

## MEDIA-04 メディアの管理用の名称・検索情報と共有する説明を編集する

- **利用者**: 編集権限を持つメンバー
- **目的**: メンバーが、メディアを後から見つけやすくし、使用箇所で使う説明の元を用意する
- **要件**: 4.4

### 正常系

1. メンバーは、メディアの管理でメディアを開く
2. メンバーは、管理用の名称と検索情報を編集する。管理用の名称と検索情報は、メディアの検索に使い、公開表示に使わない
3. メンバーは、共有する説明を編集する。共有する説明は、代替テキストとキャプションである
4. CMS は、共有する説明の変更が、既存の使用箇所の説明と公開表示を書き換えないことを示す
5. メンバーは、保存する。CMS は、保存の結果を示す
6. 以後にそのメディアを挿入した使用箇所には、保存後の共有する説明が写る。既存の使用箇所の説明を変える場合、メンバーは各コンテンツで説明を直す（MEDIA-05）

### 異常系

- **入力エラー**: 管理用の名称を空にした保存と、長さの上限を超える入力の保存は、項目と理由を示して拒否される。入力は画面に残る。メンバーは、入力を直して保存し直す
- **リソース不在**: 編集の途中でメディアが削除された場合、保存は拒否される。メンバーがメディアを開き直すと、存在しない対象（`spec/scenario/index.md` の「共通の規則」）になる
- **操作の取り消し**: メンバーが保存せずに編集をやめると、名称、検索情報、共有する説明は変わらない

## MEDIA-05 使用箇所ごとの説明を設定する

- **利用者**: 編集権限を持つメンバー
- **目的**: メンバーが、メディアを使う文脈に合った代替テキストとキャプションを、使用箇所ごとに設定する
- **要件**: 4.3, 4.4

### 正常系

1. メンバーは、コンテンツの編集画面で、メディアの項目、または本文の画像を選ぶ
2. CMS は、その使用箇所の説明を示す。挿入した直後の説明には、メディアの共有する説明が入っている
3. メンバーは、代替テキストとキャプションを、その使用箇所に合わせて入力する
4. メンバーは、共有する説明が後から変わった場合、現在の共有する説明をその使用箇所へ取り込める。取り込みは、その使用箇所の説明を置き換える
5. メンバーは、下書きを保存する。使用箇所の説明は、コンテンツの内容として保存される
6. 公開中のコンテンツでは、保存しても公開表示は変わらない。公開権限を持つメンバーがコンテンツを公開すると、説明が公開表示に反映される（PUB-01）
7. 同じメディアのほかの使用箇所の説明と、メディアの共有する説明は変わらない

### 異常系

- **入力エラー**: 説明が長さの上限を超える場合、CMS は保存を拒否して、項目と理由を示す。入力は編集画面に残る。メンバーは、説明を短くして保存し直す
- **非推奨の項目**: 非推奨の項目の説明は読み取り専用である
- **リソース不在**: 共有する説明が未設定のメディアでは、取り込める説明がないことを示す。メンバーは、説明を直接入力する
- **操作の取り消し**: メンバーが保存せずに編集画面を離れると、使用箇所の説明は変わらない。保存した変更は、公開中のコンテンツでは下書きの破棄で取り消す（EDIT-09）

## MEDIA-06 メディアの使用箇所を確認する

- **利用者**: メンバー
- **目的**: メンバーが、メディアがどのコンテンツで使われているかを知り、非公開化・削除・付け替えの影響を判断する
- **要件**: 4.4

### 正常系

1. メンバーは、メディアの管理でメディアを開き、使用箇所の一覧を確認する
2. CMS は、使用箇所ごとに、コンテンツ、モデル、内容の種類、コンテンツの置き場所と、その内容の中でメディアを使っている項目の位置を示す。同じ内容の複数の位置で使っている場合は、一件の中に位置を並べて示す
3. CMS は、公開使用があるかどうかと、メディアの公開範囲を示す
4. メンバーは、使用箇所から、そのコンテンツを開く。置き場所がごみ箱の使用箇所からは、ごみ箱のそのコンテンツを開く

### 異常系

- **リソース不在**: 使用箇所がないメディアでは、CMS は使用箇所がないことを示す

## MEDIA-07 公開使用のないメディアを非公開化する

- **利用者**: メディア公開権限を持つメンバー
- **目的**: メンバーが、公開内容で使われなくなったメディアの配信を止める
- **要件**: 4.4, 9.1

### 正常系

1. メンバーは、メディアの管理で公開のメディアを開き、非公開化を選ぶ。公開使用がなくなっても、CMS はメディアの公開を自動で取り消さない
2. CMS は、公開使用がないことを確かめ、非公開化の影響を示す
   - CMS が管理する配信で、資格を示さない要求による、元の画像と派生形式の新しい取得を拒否する
   - 表示アプリ、その CDN、ブラウザが保持した内容と、外部が保存・複製した内容は回収できない。保持した内容は、保持の期限まで表示され得る
3. メンバーは、影響を確認して確定する
4. CMS は、メディアと派生形式を同時に非公開にし、非公開になったことを示す。確定の後の配信は、「共通の規則」の配信の入口の規則に従う
5. 非公開にしたメディアは、それを使用するコンテンツを公開したとき、再び公開される

### 異常系

- **公開使用がある**: 公開使用があるメディアでは、CMS は、手順 2 で影響の代わりに公開使用の使用箇所を示し、非公開化を確定しない。メンバーは、使用するコンテンツの公開内容からメディアを外して公開するか、そのコンテンツの公開を取り消してから、非公開化し直す
- **確定までに公開使用が生じた**: 非公開化が確認の後の変化として挙げるのは、そのメディアと、その公開使用である。影響の確認から確定までの間に、そのメディアが変わった場合と、そのメディアを使用するコンテンツが公開された場合、非公開化は拒否される。CMS は、生じた公開使用を示す
- **権限不足**: 必要な権限は `spec/scenario/index.md` の「権限」に従う。編集権限だけを持つメンバーは、メディア公開権限を持つメンバーに非公開化を依頼する
- **リソース不在**: 既に非公開のメディアには、非公開化の操作を示さない。確定までにメディアが削除された場合、非公開化は拒否される。メンバーがメディアを開き直すと、存在しない対象（`spec/scenario/index.md` の「共通の規則」）になる
- **操作の取り消し**: 非公開にしたメディアを再び公開するには、使用するコンテンツを公開する

## MEDIA-08 メディアを削除する

- **利用者**: 編集権限を持つメンバー（公開のメディアはメディア公開権限を持つメンバー）
- **目的**: メンバーが、使われていないメディアをワークスペースから取り除く
- **要件**: 4.4, 7.2, 9.1

必要な権限は、`spec/scenario/index.md` の「権限」に従う。

### 正常系

1. メンバーは、メディアの管理でメディアを開き、削除を選ぶ
2. CMS は、使用箇所がないことを確かめ、削除の影響を示す
   - 削除は完全削除であり、ごみ箱へ移らず、戻せない
   - 派生形式も同時に削除する
   - 公開のメディアでは、配信が止まる。表示アプリ、その CDN、ブラウザが保持した内容と、外部が保存・複製した内容は回収できない
3. メンバーは、影響を確認して確定する
4. CMS は、メディアと派生形式を削除し、削除したことを示す。メディアは、一覧と検索に現れなくなる。削除の確定の後の配信は、「共通の規則」の配信の入口の規則に従う

### 異常系

- **使用箇所がある**: コンテンツの公開内容、下書き、保持対象の履歴の版のいずれかから使われているメディアの削除は拒否される。コンテンツの置き場所によらない。CMS は、使用箇所と、内容の種類と置き場所ごとの解消方法を示す
  - 通常の管理対象のコンテンツの下書き: コンテンツを編集してメディアを外し、保存する。編集権限を必要とする
  - 公開内容: コンテンツを編集してメディアを外し、公開する。編集権限と公開権限を必要とする
  - ごみ箱のコンテンツの下書き: コンテンツを完全削除する。または、復元してからメディアを外す。どちらも削除権限を必要とし、メディアを外す編集には編集権限を必要とする
  - 履歴の版（置き場所によらない）: 削除の確認の中で、示された版を一件ずつ明示して対象に加える。対象に加えた版は、メディアと同じ確定で削除する。CMS は、対象に加えた版について EDIT-17 の確認と同じ内容を示す。または、コンテンツを完全削除する（PUB-07）。どちらも削除権限を必要とする。保持方針による自動整理でその版が整理された後も、使用は解消する
- **解消の操作**: CMS は、メディアの削除に伴って、使用箇所のコンテンツと履歴を自動で変更・削除しない。削除する履歴の版は、メンバーが明示して対象に加えたものに限る。メンバーは、履歴の版のほかの使用箇所について、上の権限で解消の操作を明示的に行ってから、削除し直す
- **確定までに使用箇所が生じた**: 削除が確認の後の変化として挙げるのは、そのメディアと、その使用箇所である。影響の確認から確定までの間に、そのメディアが変わった場合と、そのメディアを使う下書きが保存された場合、削除は拒否される。CMS は、生じた使用箇所を示す
- **スキーマの反映の適用中**: 履歴の版を対象に加えた削除の扱いは、`spec/scenario/index.md` の「スキーマの反映の適用中」に従う
- **権限不足**: 編集権限だけを持つメンバーは、公開のメディアの削除または非公開化を、メディア公開権限を持つメンバーに依頼する。削除権限を持たないメンバーには、履歴の版を対象に加える操作を示さない。そのメンバーは、削除権限を持つメンバーに、版の削除（EDIT-17）を依頼する
- **操作の取り消し**: 確定した削除は戻せない。同じファイルを再び使う場合は、新しいメディアとして登録する（MEDIA-01）

## MEDIA-09 使用中のメディアを、新しく登録したメディアへ付け替える

- **利用者**: 編集権限を持つメンバー
- **目的**: メンバーが、使用中のメディアを、別のファイルのメディアに置き換える
- **要件**: 4.4

登録済みのメディアの実体は変わらない。差し替えは、新しいメディアの登録と、使用箇所の付け替えで行う。

### 正常系

1. メンバーは、元のメディアの使用箇所を一覧する（MEDIA-06）
2. メンバーは、使用箇所のコンテンツの編集画面で、元のメディアを新しいメディアに付け替える。最初の使用箇所では、新しいファイルをドロップするか貼り付けて、新しいメディアの登録と付け替えを一度に行う（MEDIA-02）。残りの使用箇所では、登録した新しいメディアを選ぶ（MEDIA-03）。使用箇所の説明は、付け替えても残る
3. メンバーは、下書きを保存する。公開中のコンテンツでは、保存しても配信は変わらない
4. 公開権限とメディア公開権限を持つメンバーが、コンテンツを公開する（PUB-01）。新しいメディアは、公開の確定に合わせて公開される
5. メンバーは、元のメディアの使用箇所の一覧で、下書きと公開内容の使用箇所が残っていないことを確かめる
6. 元のメディアは、公開使用がなくなっても公開のままである。使わなくなった元のメディアは、MEDIA-08 で削除する。残る履歴の版からの使用は、削除の確認の中で版を対象に加えて、同じ確定で解消する。必要な権限は MEDIA-08 に従う
7. 使用箇所が多い場合、開発者が、スクリプトからの値の書き換えで使用箇所をまとめて付け替える（APP-10）

### 異常系

- **入力エラー**: 新しいファイルが対応形式と容量の上限を満たさない場合、登録も付け替えもされない（MEDIA-02）。本文の画像の使用箇所は、画像でないメディアに付け替えられない。メディアの項目の使用箇所は、どの対応形式のメディアにも付け替えられる
- **権限不足**: 公開権限またはメディア公開権限を持たないメンバーは、付け替えを下書きとして保存するところまでを行う。公開は、公開権限とメディア公開権限を持つメンバーに依頼する
- **リソース不在（使用箇所）**: 元のメディアに使用箇所がない場合、付け替えは不要である。メンバーは、以後のコンテンツで新しいメディアを使う
- **付け替えられない使用箇所**: ごみ箱のコンテンツは、通常の編集の対象でない。ごみ箱のコンテンツの下書きを付け替える場合は、コンテンツを復元してから編集する。履歴の版の使用箇所は、置き場所によらず、付け替えの対象でない。履歴の版が残る間、元のメディアは削除できない
- **非推奨の項目**: 非推奨の項目の使用箇所は、編集画面で付け替えられない。開発者が、値の書き換えで付け替える（APP-10）
- **操作の取り消し**: 付け替えを途中でやめると、付け替えを終えたコンテンツは新しいメディアを、残りのコンテンツは元のメディアを使い続ける。メンバーは、元のメディアの使用箇所の一覧で残りを確認して、続きを行う。保存した付け替えを取りやめる場合、公開中のコンテンツでは下書きを破棄する（EDIT-09）

## MEDIA-10 派生形式の生成状況と失敗を確認する

- **利用者**: メンバー、開発者
- **目的**: メンバーと開発者が、画像の派生形式を配信できる状態かを知り、失敗に対処する
- **要件**: 4.4

### 正常系

1. メンバーは、メディアの管理で画像を開き、スキーマで定義した派生形式ごとの生成状況を確認する。生成状況は、生成中、生成済み、失敗のいずれかである
2. 生成済みの派生形式では、画像形式、幅、高さを確認する
3. 開発者は、派生形式の定義を追加・変更したスキーマを反映する（SMIG-07）。CMS は、登録済みの画像にも新しい定義を適用する
4. 開発者は、メディアの一覧を生成状況で絞り込み、生成中と失敗の画像を確認する
5. 定義を変更した派生形式では、新しい派生形式を配信できるまで、変更前の派生形式の配信が続く。取得結果は、生成済みの派生形式だけを生成済みとして返す（APP-02）
6. 派生形式は、元のメディアの公開範囲に従う。非公開のメディアの派生形式は、生成済みでも公開されない
7. 開発者は、生成中と失敗の画像がなくなったことを確かめてから、新しい派生形式を前提とする表示アプリを配信する

### 異常系

- **生成の失敗**: 生成に失敗した派生形式では、CMS は失敗したことと理由を示す。取得結果は、その派生形式を生成済みとして返さない。編集権限を持つメンバーは、失敗した派生形式の生成をやり直す
- **元の画像が原因の失敗**: 生成をやり直しても失敗する画像は、編集権限を持つメンバーが、別のファイルを新しいメディアとして登録して付け替える（MEDIA-09）
- **定義が原因の失敗**: 同じ派生形式が多くの画像で失敗する場合、開発者は、派生形式の定義を直して反映する
- **権限不足**: 共通の規則に従う
- **リソース不在**: 派生形式を定義していないスキーマと、画像でないメディアでは、生成状況を示さない
