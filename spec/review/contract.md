# 契約

出典は `spec/requirements.md`。各項目の規則の全文は出典の節が正で、台帳は要求の分母を与える。出典欄の数字は `spec/requirements.md` の節番号。

範囲にする層は scenario / pages / domains / usecases / flows / testcases。

## 前提

着手時にユーザーが決めたこと。

- 出典は `spec/requirements.md`。`spec/idea.md` には触れない
- 全層を一度に作る
- 出典 12 の「設計で決める事項」は設計者が決め、主要な判断を完了報告で述べる。方向が割れる判断だけユーザーに聞く
- 技術設計は `AGENTS.md` の構成（ヘキサゴナル + DDD、UnitOfWork、outbox、`packages/core` と `apps/web`）に乗せる。開発者向けの SDK / CLI は新しい `packages/*` / `apps/*` として設計する

## 4.2 コンテンツの状態

| ID | 要求 | 出典 |
| --- | --- | --- |
| C4.2-01 | 一件のコンテンツは、変わらないコンテンツID と、公開内容・下書きをそれぞれ最大一つ持ち、少なくとも一方を持つ。下書きはコンテンツごとに一つで編集者の間で共有する | 4.2 |
| C4.2-02 | 公開状態（未公開・公開中）は公開内容の有無で決まる。下書きの有無は公開状態と独立して確認できる。最新の内容は、下書きがあれば下書き、なければ公開内容 | 4.2 |
| C4.2-03 | コンテンツは通常の管理対象またはごみ箱のいずれかにある。ごみ箱のコンテンツは未公開とする。新規コンテンツは未公開として作成する | 4.2 |
| C4.2-04 | コンテンツ管理の許可による作成ではコンテンツID を指定できる。同じワークスペースに既にある ID では作成せず既にあることを示し、繰り返しても重複して作らない。完全削除したコンテンツの ID は再び指定できる。管理画面での作成と複製では CMS が ID を割り当てる | 4.2 |

| C4.2-06 | 編集は最新の内容から始め、保存すると下書きになる。公開内容と配信は、公開、公開取り消し、移行、値の書き換えでだけ変わる | 4.2 |

| C4.2-08 | 文字数・範囲・書式・件数などの制約は、公開と値の書き換えの時点で確認する。制約を強める反映は既存の公開内容を変えず、現行の制約を満たさない公開内容を配信し続ける。その公開内容を編集して保存すると違反は下書きの入力エラーになり、解消するまで公開しない | 4.2 |
| C4.2-09 | 公開中のコンテンツは下書きを破棄できる。破棄した下書きは履歴に残す | 4.2 |
| C4.2-10 | 公開を取り消すと、公開内容をなくし、最新の内容を下書きとして残す。下書きがあった場合は公開内容を履歴に残す。取り消しても内容を失わず編集を続けられる | 4.2, 5.1 |
| C4.2-11 | 公開中のコンテンツのごみ箱への移動と完全削除は、公開取り消しを含む操作として扱う | 4.2 |
| C4.2-12 | 値の書き換えは、コンテンツ管理の許可を持つトークンで行う。指定した項目の値だけを変え、ほかの項目と選ばなかった公開内容・下書きを変えない。下書きを公開せず、新たな下書きを作らない。下書きの書き換えは下書きを持つコンテンツにだけ行う。ごみ箱のコンテンツもごみ箱に置いたまま下書きを書き換えられる | 4.2 |
| C4.2-13 | 公開内容の値の書き換えは、書き換える項目の値が公開時の検証を満たす場合に限り行い、書き換え前の公開内容を履歴に残す。書き換えない項目に残る制約の違反は妨げない。下書きの値の書き換えは入力エラーを残してよい | 4.2 |
| C4.2-14 | 値の書き換えは、読み取った後に他の操作で変わった内容を気付かず上書きしない | 4.2 |
| C4.2-15 | 複数のコンテンツの値の書き換えを一つの操作として行える。すべての対象の検証、競合の確認、必要な権限の確認を終えてから確定し、一部だけを書き換えない | 4.2 |
| C4.2-16 | ごみ箱のコンテンツは移動時点の下書きと履歴を保持し、公開取得、プレビュー取得、通常の編集の対象にしない。移行と値の書き換えの対象とし、復元時は未公開として戻す。復元だけでは公開しない | 4.2 |
| C4.2-17 | 一意な値は公開内容の間で重複させない。一意性は公開時に確認し、同時操作でも保つ。下書き・ごみ箱・履歴の値は予約しない。下書きの保存時にも他のコンテンツの公開内容との重複を示す | 4.2 |
| C4.2-18 | CMS が管理する日時は、作成日時と、公開内容・下書きそれぞれの更新日時。取得では返す内容の更新日時を返す。下書きの保存と破棄で公開取得に返す日時を変えない | 4.2 |

## 層との対応

- C10.3-02 / C10.3-03（キーボード操作と支援技術）の最下流の層は pages。その確認（C10.4-01 のうち「管理検索、キーボード操作、支援技術による入力・エラー・状態変化の認識」）は、画面を操作する手順書（派生物の `spec/manual-tests/`）が担い、範囲の層の外にある
- D-01（実行基盤）は Cloudflare Workers。ワークスペースごとのデータ（スキーマ、コンテンツ、メディアの記録、フォーム、通知、メンバー、招待、トークン、操作履歴）は、ワークスペースごとの Durable Object が持ち、ワークスペースをまたぐデータ（アカウント、セッション、回復依頼、設置の記録、ワークスペースの名簿）は D1 が持つ（ユーザーの指定）。二つをまたぐ書き込みは一つのトランザクションにならない。spec はこれを「区画」（設置の区画と、ワークスペースごとの区画）として表し、一つの UnitOfWork は一つの区画だけを書く。spec は Durable Object と D1 の語彙を持たず、ポートの契約までを定める。アダプターの構成は `AGENTS.md` の Reference runtimes と `docs/runtime_*.md` が定める。対応環境と利用上限のうち、利用者に見える上限（件数、容量、期間）の値は、scenario の APP-12 が定める
- C5.4-06 / C8.3-16 の「未対処」は、権限を持つメンバーが再試行を始めたこと、対処済みとして記録したこと、フォームの通知ではその回答を削除したことで終わる。再試行が再び失敗すれば、未対処に戻る。対処済みの記録は、D-09（通知結果の記録）と D-13（再試行・終了条件）が設計に委ねた事項
- C6.4-04 の「新たに使えない」は、非推奨のモデルでは、そのモデルのコンテンツを新たに通常の管理対象と配信に加える操作（新規作成、複製、履歴からの復元、公開、ごみ箱からの復元）を行えないことを含む。新たに加えない操作は行える
- C6.4-04 の「読み取り専用」の対象は、非推奨の項目の値、非推奨のモデルのコンテンツ、非推奨の種類のブロックの中の値。非推奨でない項目が非推奨の選択肢を選んでいる値を、非推奨でない選択肢へ変えることと、非推奨の種類のブロックを、それを持つ非推奨でない項目から削除することは、非推奨の対象を新たに使わないので、編集画面で行える
- C4.4-03 の「CMS が管理する配信」は、CMS の配信の入口。入口は要求のたびに公開範囲を確かめ、内容を保持しない（ユーザーの指定）。出典 4.4 の長いキャッシュは、入口の先（表示アプリ、その CDN、ブラウザ）に許すもので、そこに残った内容は N-01 の範囲
- C4.4-02 の「移行に伴うメディアの公開」は、設計では生じない。移行の操作は、その内容が既に使うメディアのほかを参照しないので、移行は新たに公開するメディアを作らない
- C6.1-16 の「対象と件数」は、該当する全件の件数と、対象の先頭（上限まで）を示すことで満たす。上限を超える対象の全件の一覧は求めない
- C5.4-06 の「未対処の失敗」は、作られた通知の送信の失敗を指す。通知を作る前のイベントの配送の失敗（隔離されたイベント）は、ホスティング運営者の状態確認（C10.1-06）が担う

## 範囲外

出典 11.1 の対象外の各項目と、各節が「初期版に含めない」とする事項は設計に含めない。
