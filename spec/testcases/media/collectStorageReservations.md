# 回収できる保管の予約を回収する（`collectStorageReservations`）

「回収できる予約」は、`StorageReservation.isCollectable` が真の保管の予約を指す。

| ID | 前提条件 | 操作 | 期待結果 |
|---|---|---|---|
| TC-media-collectStorageReservations-01 | ワークスペースに、登録の、回収できる予約がある。確定した実体があり、メディアは登録されていない | そのワークスペースを指定して実行する | 予約が無くなる。そのメディアの ID の消去待ちが記録される。実体は、まだメディアの保管先にある。回収した予約の件数 1 を返す。続けて「消去待ちの実体を消去する」を実行すると、その実体がメディアの保管先から無くなり、消去待ちの記録は残らない |
| TC-media-collectStorageReservations-02 | ワークスペースに、登録の、回収できる予約がある。確定していない試みの内容だけがあり、実体は無い | そのワークスペースを指定して実行し、続けて「消去待ちの実体を消去する」を実行する | 予約が無くなる。試みの内容もメディアの保管先から無くなり、その試みは `commit` できない。消去待ちの記録は残らない |
| TC-media-collectStorageReservations-03 | ワークスペースに、回収できない予約がある。確定した実体がある | そのワークスペースを指定して実行する | 実体と予約は残る。消去待ちの記録はできない。件数 0 を返す |
| TC-media-collectStorageReservations-04 | ワークスペースに、派生形式の生成の、回収できる予約がある。その世代は生成の対象のままで、確定した実体がある | そのワークスペースを指定して実行する | 予約が無くなる。消去待ちの記録はできず、実体は残る。派生形式の記録の値と `version` は変わらない |
| TC-media-collectStorageReservations-05 | ワークスペースに、派生形式の生成の、回収できる予約がある。その世代は生成の対象から外れている、またはそのメディアは削除済み。確定した実体がある | そのワークスペースを指定して実行する | 予約が無くなる。その実体の消去待ちが記録される |
| TC-media-collectStorageReservations-07 | ワークスペースに、登録の、回収できる予約がある。定期ジョブが予約を読んだ後、回収の確定の前に、その登録が確定する | そのワークスペースを指定して実行する | その予約を飛ばす。消去待ちの記録はできない。登録したメディアの実体は残り、配信できる |
| TC-media-collectStorageReservations-08 | ワークスペースに、回収できる予約が 2 件ある。古い方の回収の確定が、同じ画像の派生形式の記録へのほかの保存と競合する | そのワークスペースを指定して実行する | 競合した予約は残り、もう 1 件は回収される。件数 1 を返す。エラーを投げない。残った予約は、次の起動が、変わった後の派生形式の記録で回収する |
| TC-media-collectStorageReservations-10 | 区画の消去を終えて `Workspace` が `closed` のワークスペースに、回収できる予約と、その処理が区画の消去の後に確定した実体がある | そのワークスペースを指定して実行し、続けて「消去待ちの実体を消去する」を実行する | 予約が無くなる。その実体がメディアの保管先から無くなり、消去待ちの記録は残らない。`StorageReservationRepository.count()` と `ObjectRemovalRepository.count()` は 0 を返す。ドメインイベントを記録しない |
