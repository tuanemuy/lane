# プレビューの入口と通知の入口（@repo/client/next）

`packages/client` の `@repo/client/next` が公開する、Next.js のミドルウェア、関数、ルートハンドラー。契約は [app-api.md](../../usecases/app-api.md) の「入口」が定める。CMS の応答は、試験用の入口が返す。通知の署名は、[verifyNotification.md](verifyNotification.md) の K、B、T、S と同じ。「プレビュー先の URL」は、モデルのプレビュー先の経路 `/articles/hello` に、引き換えの値のクエリを添えた URL を指す。

## プレビューの入口

| ID | 前提条件 | 操作 | 期待結果 |
|---|---|---|---|
| TC-client-nextHandlers-01 | CMS は、引き換えの値に、引き換えたトークンと有効期限を返す | メンバーのブラウザが、プレビュー先の URL を開く | 入口は、トークンを添えずに引き換えを要求し、引き換えたトークンと有効期限を、サーバー側のセッションに結び付けて、`/articles/hello` へ移す。ブラウザへの応答（本文、ヘッダー、移る先の URL）は、トークンの値を含まない |
| TC-client-nextHandlers-02 | 上の引き換えの後 | 同じセッションの要求で、プレビュー用のクライアントを得る関数を呼び、そのクライアントでプレビュー取得を呼ぶ | クライアントを返す。プレビュー取得の要求は、引き換えたトークンを添える |
| TC-client-nextHandlers-03 | トークンを結び付けていないセッション | プレビュー用のクライアントを得る関数を呼ぶ | `null` を返す |
| TC-client-nextHandlers-04 | 上の引き換えの後、有効期限を過ぎた | 同じセッションの要求で、プレビュー用のクライアントを得る関数を呼ぶ | `null` を返す |
| TC-client-nextHandlers-05 | 上の引き換えの後 | 同じセッションで、プレビューを終える入口を開いた後に、プレビュー用のクライアントを得る関数を呼ぶ | `null` を返す |
| TC-client-nextHandlers-06 | CMS は、引き換えを拒否する（使用済みの値） | メンバーのブラウザが、プレビュー先の URL を開く | セッションにトークンを結び付けない。`/articles/hello` へ移さず、引き換えを拒否されたことを示す |

## 通知の入口

| ID | 前提条件 | 操作 | 期待結果 |
|---|---|---|---|
| TC-client-nextHandlers-07 | 入口は、秘密情報 K と開発者の関数を指定して置いてある。開発者の関数は正常に終わる | 本文 B、ヘッダー T、S の通知を入口へ送る | 開発者の関数を、B の通知の内容を渡して一度呼ぶ。応答の状態は 204 |
| TC-client-nextHandlers-08 | 同上 | S が、K と違う秘密情報で計算した値の通知を入口へ送る | 開発者の関数を呼ばない。通知を破棄する。応答の状態は 401 |
| TC-client-nextHandlers-09 | 入口は、秘密情報 K と開発者の関数を指定して置いてある。開発者の関数は失敗を投げる | 本文 B、ヘッダー T、S の通知を入口へ送る | 開発者の関数を一度呼ぶ。応答の状態は 500 |
| TC-client-nextHandlers-10 | 同上 | 同じ通知（同じ `notificationId`）を、二度入口へ送る | 二度とも、開発者の関数を呼ぶ。渡す通知の内容の `notificationId` は等しい。入口は、処理済みの通知を保持しない |
