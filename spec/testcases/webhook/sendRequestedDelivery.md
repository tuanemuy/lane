# 送信を求められた通知を送る

断りが無い限り、次を前提にする。

- ワークスペースは、名簿で開設済みで、`active`
- 「送信の要求」は、`webhook.delivery_requested`（ペイロードは、通知の ID と宛先の ID）を指す。操作は、その消費
- 「送信待ち（最初）」は、通知の作成が作った、最初の試行を待つ送信。「送信待ち（手動）」は、手動再試行を受け付けた送信。どちらも、次の試行の時刻を過ぎている

| ID | 前提条件 | 操作 | 期待結果 |
|---|---|---|---|
| TC-webhook-sendRequestedDelivery-01 | 宛先 A と B の送信が送信待ち（最初）の通知。A は 200 番台で応答する | A を指す送信の要求を受け取る | A へ一回送る。B へは送らない。A の送信は送信成功になる。成功の日時は、消費者が送る前に読んだ時刻で、A が受け取った要求の `X-Lane-Timestamp` と秒の単位で同じ時刻。B の送信は送信待ちのまま変わらない。操作履歴に残さない |
| TC-webhook-sendRequestedDelivery-02 | 公開中のコンテンツの一意な値を変えた公開の通知。そのコンテンツを、公開中の別のコンテンツが参照している。宛先 A の送信が送信待ち（最初） | A を指す送信の要求を受け取る | A へ送る通知の内容は、通知の ID（`notificationId`）、通し番号（`sequence`）、変更した対象のコンテンツID とモデルのキー、変更の種類、一意な値の変更前と変更後、参照元のコンテンツID とモデルのキーを持つ。操作の ID、実行者、ワークスペースの ID、確定した日時を持たない |
| TC-webhook-sendRequestedDelivery-03 | スキーマの反映による通知（通知の元は `schemaApply`）。宛先 A の送信が送信待ち（最初） | A を指す送信の要求を受け取る | A へ送る通知の内容の `schemaVersion` は、反映後のスキーマの版。コンテンツの操作による通知の内容の `schemaVersion` は `null` |
| TC-webhook-sendRequestedDelivery-05 | 宛先 A の送信が送信待ち（最初）。A は 500 で応答する | A を指す送信の要求を受け取る | 正常に終わる。A の送信は送信待ちのまま、次の試行は自動の 2 回目、次の試行の時刻は、消費者が送る前に読んだ時刻から `DeliveryPolicy.retryDelaysMs` の最初の間隔の後、直前の試行は、その時刻と、失敗 `undelivered`（`rejected`、500）になる。送信失敗としては示さない |
| TC-webhook-sendRequestedDelivery-06 | 宛先 A の送信が送信待ち（最初）。A の秘密情報の保護を解けない | A を指す送信の要求を受け取る | 何も送らない。A の送信は、`notSent`（`secret_unavailable`）の送信失敗（未対処）になる。送信待ちのまま残らない |
| TC-webhook-sendRequestedDelivery-07 | 宛先 A の送信が送信待ち（最初）、宛先 B の送信が送信待ち（手動）の通知。送信の要求の確定の後に、A と B が削除された | A を指す送信の要求と、B を指す送信の要求を受け取る | 何も送らず、正常に終わる。A と B の送信は、`notSent`（`endpoint_deleted`）の送信失敗（未対処）になる |
| TC-webhook-sendRequestedDelivery-09 | 宛先 B の送信が送信待ち（手動）の通知。B は 500 で応答する | B を指す送信の要求を受け取る | 正常に終わる。B の送信は送信失敗（未対処）になり、失敗は新しい失敗（`undelivered`、`rejected`、500）になる。送信待ちに戻らず、自動の再試行を行わない |
| TC-webhook-sendRequestedDelivery-12 | 最初の試行が失敗し、次の試行の時刻を過ぎた送信待ち（自動の 2 回目）の送信。定期ジョブはまだ送っていない。宛先は 200 番台で応答する | その送信を指す、同じ送信の要求をもう一度受け取る（再配送） | その宛先へ一回送る。送信は送信成功になる。消費者は、読んだ時点の送信が待つ、時刻を過ぎた試行（自動の 2 回目）を送る |
| TC-webhook-sendRequestedDelivery-13 | 送信成功になった送信と、最初の試行が失敗し、次の試行の時刻を過ぎていない送信待ち（自動の 2 回目）の送信 | それぞれの送信を指す、同じ送信の要求をもう一度受け取る | 何も送らない。どちらの送信も変わらない |
| TC-webhook-sendRequestedDelivery-15 | 宛先 A の送信が送信待ち（最初）。A は 500 で応答する。送信の要求は、作成から `DeliveryPolicy.requestGraceMs` が過ぎた後に届いた。消費者が送る前に送信を読んだ後、消費者の結果の記録の前に、定期ジョブが同じ試行（最初の試行）を送り、その失敗を記録して確定した | A を指す送信の要求を受け取り、A へ送った後に結果を記録する | エラーにせずに終える。消費者の試行の結果は記録されない。A の送信は、自動の 2 回目を待つ送信待ちのままで、試行の番号は一つだけ進む |
| TC-webhook-sendRequestedDelivery-17 | 宛先 A の送信が送信待ち（最初）。A は 200 番台で応答する。結果の記録が、同じ送信へのほかの書き込みと競合する | A を指す送信の要求を受け取る | `ConflictError`（`STALE_VERSION`）を投げる。A は通知を受け取っている。その試行の結果は記録されず、A の送信は、先に確定した書き込みの状態のまま |
| TC-webhook-sendRequestedDelivery-22 | 宛先 A の送信が送信待ち（最初）。A は 200 番台で応答する。消費者が送信を読んだ後、A へ送る前に中断した | 中断の後に送信を読み、同じ送信の要求をもう一度受け取る（再配送） | 中断の後、A の送信は送信待ち（最初）のまま変わらず、A は通知を受け取っていない。再配送では、A へ一回送り、送信は送信成功になる |
| TC-webhook-sendRequestedDelivery-21 | 宛先 A の送信が送信待ち（最初）。A は 200 番台で応答する。消費者が A へ送った後、結果の記録の前に中断し、送信は送信待ち（最初）のまま残った | 同じ送信の要求をもう一度受け取る（再配送） | A へもう一度送る。A は、同じ `notificationId` と `sequence` の通知を二度受け取る。送信は送信成功になる |
