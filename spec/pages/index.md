# ページ

管理画面の画面構成。各画面の目的、機能、状態を定め、すべてのシナリオを画面または画面以外の手段に対応させる。上流は `spec/scenario/`。用語は `spec/requirements.md` の 1 章に、権限の名前は `spec/scenario/index.md` の「権限」に従う。

管理画面の利用の手段は、`spec/scenario/authentication.md` の「共通の規則」に従う。

## 共通の規則

全画面に適用する。各画面は、この規則に加わる分だけを書く。

### ナビゲーション

P05、P06 と P08 から P28 は、共通のナビゲーションを持つ。ナビゲーションは次を示す。

- 利用中のワークスペースの名称と、所属するワークスペースの一覧。一覧から選ぶと、そのワークスペースへ切り替わる。ワークスペースの選択（P06）も開ける
- スキーマが定義するモデル。表示名称と順序はスキーマに従う。非推奨のモデルは非推奨と示す。モデルごとに、入力エラーを持つ下書きの現在の件数と、制約を満たさない公開内容の現在の件数を示す（EDIT-15）。件数は、その条件で絞り込んだそのモデルの P08 の件数と一致する。件数を選ぶと、その条件で絞り込んだ P08 を開く。単一モデルでは P09 を開く
- メディア（P12）、ごみ箱（P11）
- P14、P16、P17、P19、P20、P22 から P28 のうち、メンバーに示す画面
- 未対処の失敗と不整合の表示
- アカウント設定（P05）とログアウト

複数件を持つモデルを選ぶと P08 を、単一モデルを選ぶと一覧を挟まずに P09 を開く。

ワークスペースを開いたとき（ログインの後、切り替えの後、参加の後）に開く画面を「最初の画面」と呼ぶ。最初の画面は、「画面の一覧」の「示す相手」にそのメンバーが当たる画面から選ぶ。

- モデルがあるワークスペースでは、スキーマの順序で先頭のモデルを開く。先頭のモデルが複数件を持つモデルなら P08 を、単一モデルなら P09 を開く。
- モデルが無いワークスペースでは、P14、P16、P17、P19、P20、P22 から P28 のうち、そのメンバーが「示す相手」に当たる画面を、この順で先頭から一つ開く。当たる画面が無いメンバーには、P08 を「モデルが無い」状態で開く。

次の人には、ナビゲーションは、ワークスペースの選択（P06）、アカウント設定（P05）、ログアウトだけを示す。ワークスペースの名称、所属するワークスペースの一覧、モデル、ワークスペースの画面、未対処の失敗と不整合の表示は示さない。

- 所属するワークスペースが無い人
- 多要素認証の設定を求められて P05 にいる人

### 権限

- 「画面の一覧」の「示す相手」に当たらないメンバーには、その画面をナビゲーションに示さない。URL を直接開いた場合、内容を示さず、必要な権限を示す。
- コンテンツ、メディア、履歴、ごみ箱の画面（P08 から P13）は、編集権限を持たないメンバーに、内容を読み取り専用で示す。
- 権限を持たない操作の示し方と、画面を開いた後に権限が変わるなどして権限を持たない操作が要求された場合の扱いは、`spec/scenario/index.md` の「管理画面の操作」の「権限の不足」に従う。
- 操作を示す条件は、各シナリオの異常系が定める「操作を示さない」対象に従う。

### ワークスペース

- 画面は、利用中のワークスペースのデータだけを示す。
- ワークスペースの切り替えは、ナビゲーションの所属するワークスペースの一覧、または P06 から選んで行う。切り替えに再ログインを必要としない。
- 所属の一覧に無いワークスペースの扱いは、`spec/scenario/index.md` の「管理画面の操作」の「許可されていないワークスペース」に従う。ログインした人がその URL を開いた、またはその画面で操作した場合、P06 へ移る。
- 多要素認証を必須にしたワークスペースを未設定のまま開いたメンバーは、P05 へ移る。

### 未対処の失敗と不整合

ナビゲーションは、次の表示を示す。表示は回答の入力内容を含まない。

| 表示 | 開く画面 |
| --- | --- |
| フォームの通知の未対処の失敗 | P17（未対処で絞り込んだ状態） |
| 表示アプリへの通知の未対処の失敗 | P28（未対処で絞り込んだ状態） |
| 参照の不整合が残る通知定義があることと、対象のフォーム | 対象のフォームの P15 |

未対処の失敗の表示の示す相手、件数、表示する間は、`spec/scenario/index.md` の「未対処の失敗」に従う。参照の不整合の表示の示す相手と、表示する間は、FORM-04 に従う。

### スキーマの反映の適用中

スキーマの反映の適用中に示すもの、止める操作、利用者の次の操作は、`spec/scenario/index.md` の「スキーマの反映の適用中」と、「管理画面の操作」の「スキーマの反映の適用中」に従う。適用中であることを常に示す画面は P08 から P11。

### 確認と確定

- 確認は、操作を始めた画面の上に示す。別の画面へ移らない。
- 確認で示した内容が確定までに変わった場合の扱いは、`spec/scenario/index.md` の「管理画面の操作」の「確認した内容での確定」に従う。
- 複数の対象を扱う操作の上限と確定の規則は、`spec/scenario/index.md` の「複数の対象を扱う操作」に従う。各画面は、この規則から導ける拒否を、状態として書かない。
- 取り消せない操作は、確認で取り消せないことを示す。
- 公開内容を変える操作の結果の示し方は、`spec/scenario/publishing.md` の「共通の規則」に従う。

### 未保存の入力

- 未保存の入力の確認と保持は、`spec/scenario/index.md` の「管理画面の操作」の「未保存の入力」に従う。
- 秘密情報の示し方は、`spec/scenario/index.md` の「管理画面の操作」の「秘密情報」に従う。

### セッション

期限を過ぎたセッションでの操作の扱いは、`spec/scenario/index.md` の「管理画面の操作」の「セッションの期限切れ」に従う。画面は、再ログインを画面の上で求める。

### 共通の状態

各画面は次の状態を取る。各画面の「状態」は、これ以外の状態を書く。拒否された操作の表示は「操作の失敗」が定める。各画面は、理由と対象のほかに示すものがある拒否だけを、状態として書く。

| 状態 | きっかけ | 示すもの |
| --- | --- | --- |
| 読み込み中 | 画面を開く、条件を変える | 内容の位置に、読み込み中であること |
| 読み込みの失敗 | 通信断、CMS の失敗、設置が利用者の要求を受け付けない状態（`spec/scenario/hosting.md` の「設置の状態」） | 失敗の理由と、読み込み直す操作 |
| 対象が存在しない | 開いた対象が削除済み、または存在しない | `spec/scenario/index.md` の「存在しない対象」が示すものと、一覧へ戻る操作 |
| 入力エラー | 保存または確定した入力が受け付けられない | 「言葉」が定める示し方の、項目ごとのエラー。入力を保持する |
| 操作の確認 | 確認を伴う操作を始める | 各画面の「機能」が定める確認の内容 |
| 操作中 | 操作を確定する | 操作が進行中であること。同じ操作を重ねて受け付けない |
| 操作の成功 | 操作が確定する | 操作の結果 |
| 操作の失敗 | 操作が拒否される、または失敗する | 理由と対象。入力を保持する |

一覧の画面は、加えて次の状態を取る。

| 状態 | きっかけ | 示すもの |
| --- | --- | --- |
| 空 | 対象が一件も無い | 対象が無いこと |
| 該当なし | 条件に該当する対象が無い | `spec/scenario/index.md` の「一覧の絞り込み」の該当なしが示すもの |
| 条件の誤り | 絞り込みの条件を受け付けられない | `spec/scenario/index.md` の「一覧の絞り込み」の条件の誤りが示すもの |

### キーボード操作と支援技術

- キーボードだけで完了できる操作（`spec/scenario/index.md` の「管理画面の操作」の「キーボード操作」）は、ログイン、検索、コンテンツ編集、本文の標準の編集、メディアの選択、項目の並べ替え、保存、プレビュー、公開、回答の閲覧・削除、運用設定の変更を含む。
- フォーカスの位置を常に示す。画面の上に示す確認と選択は、フォーカスを中に移し、閉じると元の位置へ戻す。フォーカスを移動できなくなる状態を作らない。
- 入力項目に、支援技術から識別できる名称を付ける。必須条件、説明、項目ごとのエラーを、項目に関連付ける。
- エラーと状態を、色だけで伝えない。
- 保存状況、操作の結果、エラー、読み込みの完了などの状態の変化を、支援技術へ伝える。

### 言葉

操作の結果、保存状況、エラーの理由と、入力の誤りと不足の示し方は、`spec/scenario/index.md` の「管理画面の操作」の「エラーの示し方」に従う。移行と復元で生じた問題は、該当する操作とコンテンツに結び付けて示す。

## 認証

### P01 ログイン

- **目的**: 本人であることを示して、管理画面の利用を始める。
- **機能**:
  - メールアドレスとパスワードでログインする
  - 多要素認証を設定した人は、続けて確認コードを入力する
  - P02 へ移る
- **状態**:
  - 資格情報の入力: 画面を開いたとき
  - 確認コードの入力: 資格情報が正しく、多要素認証を設定しているとき
  - ログインの失敗: 資格情報または確認コードが受け付けられないとき。登録のないメールアドレスも、資格情報の誤りと同じに示す
  - 試行の制限中: 失敗が繰り返されたとき。再び試せる時期を示す
  - ログイン済み: ログインが成功したとき。開くワークスペースは、AUTH-02 の手順 3 に従う。ログインが必要な画面、またはログインの要求の P04 から来た場合は、元の画面へ戻る。参加済みの P04 から来た場合は、参加したワークスペースの最初の画面を開く
- **シナリオ**: AUTH-02, SDEV-04

### P02 アクセス回復の申請

- **目的**: ログインできない人が、回復用の URL を受け取る。
- **機能**:
  - メールアドレスを入力して、回復を申請する
- **状態**:
  - 入力: 画面を開いたとき
  - 申請済み: 申請を送ったとき。アカウントの有無によらず、同じ内容を示す
  - 外部メールを使えない設置: 回復のメールを送れないことと、ホスティング運営者へ依頼することを示す
- **シナリオ**: AUTH-04

### P03 パスワードの再設定

- **目的**: 回復用の URL から、新しいパスワードを設定して、管理画面の利用を始める。
- **機能**:
  - 新しいパスワードを設定する
  - 多要素認証を設定した人は、確認コードを入力する。認証アプリを使えない場合は、多要素認証の解除を選ぶ
- **状態**:
  - 入力: 有効な URL を開いたとき
  - URL が無効: 期限切れ、使用済み、失効済みの URL を開いたとき。理由を示す。理由を示す期間（AUTH-04）を過ぎた URL では、無効であることだけを示す。回復をやり直すために、P02 へ移る操作を示す
  - 再設定済み: パスワードを更新したとき。セッションを開始し、最初の画面を開く。開くワークスペースは、AUTH-02 の手順 3 に従う。所属するワークスペースが無い人には、P06 を開く。ログインの試行の制限中は、パスワードを更新したことと再び試せる時期を示し、P01 へ移る
- **シナリオ**: AUTH-04, HOST-11

### P04 招待の受諾

- **目的**: 招待された人が、ワークスペースのメンバーになる。
- **機能**:
  - 参加するワークスペース、付与される権限、有効期限を確認する。初期所有者の招待では、権限の代わりに、所有者に指定されることを示す
  - アカウントを持たない人は、名前とパスワードを設定して参加する
  - アカウントを持つ人は、ログインして参加を承認する
- **状態**:
  - アカウントの作成: アカウントを持たない人が開いたとき
  - ログインの要求: 招待の宛先のアカウントが既にあり、ログインしていないとき。アカウントだけが出来て参加が成立していない人が、招待の URL を開き直したときを含む。P01 でログインした後、この画面へ戻る
  - 参加の承認: 招待の宛先のアカウントでログインしているとき
  - 宛先が異なる: 招待の宛先と異なるアカウントでログインしているとき。そのアカウントが既にそのワークスペースのメンバーでも同じ。ログアウトを求め、ログアウトの操作を示す
  - 参加のやり直し: CMS が参加を取り下げたとき（AUTH-01 の「取り下げられた参加」）。参加を確定できなかったことを示す。招待は使われていない。同じ画面から、参加を確定し直す
  - 招待が無効: 使えない招待を開いたとき、内容を確かめた後に使えなくなった招待の参加を確定したとき。どの招待が使えないかは AUTH-01 に従う。P01 へ移る操作を示す。理由（期限切れ、使用済み、失効済み）を示す場合と、理由を示さずに同じ一つの表示で無効と示す場合の別は、AUTH-01 に従う。理由を示さない表示は、ワークスペースの情報を示さない
  - 参加済み: 参加を確定したとき。多要素認証が必須のワークスペースで、多要素認証を設定していない人だけが P05 へ移る。それ以外の人は、最初の画面へ移る。アカウントを作った人のログインを始められなかった場合（AUTH-01 の「参加は成立したが、ログインが要る」）は、参加したことを示し、P01 へ移る。ログインの試行の制限中の場合（AUTH-01 の「試行の制限中の参加」）は、参加したことと再び試せる時期を示し、P01 へ移る
- **シナリオ**: AUTH-01, HOST-04

### P05 アカウント設定

- **目的**: 自分のアカウントの多要素認証を設定・解除する。
- **機能**:
  - パスワードを入力し、認証アプリに登録して、確認コードで多要素認証を有効にする
  - パスワードと確認コードを入力して、多要素認証を解除する。多要素認証が必須のワークスペースに所属していても解除できる。解除の前に、そのワークスペースを開くときに設定を求められることを示す
- **状態**:
  - 未設定: 多要素認証を設定していないとき
  - 設定の途中: 認証アプリに登録する情報を示しているとき。やめると有効にならない。確認コードが誤っている場合は、認証アプリへの登録からやり直せる
  - 設定済み: 多要素認証を有効にしたとき
  - 設定を求められている: 多要素認証が必須のワークスペースを未設定のまま利用しようとしたとき。設定を終えると、そのワークスペースを開く。P07 から来た場合は、P07 へ戻る
- **シナリオ**: AUTH-03

### P06 ワークスペースの選択

- **目的**: 所属するワークスペースから、利用するワークスペースを選ぶ。
- **機能**:
  - 所属するワークスペースを一覧する。所属しないワークスペースと、利用終了の途中または利用を終了したワークスペースは示さない
  - 利用するワークスペースを選ぶ
- **状態**:
  - 一覧: 画面を開いたとき
  - 利用できないワークスペース: 所属の一覧に無いワークスペースを開いた、またはその画面で操作したとき。示すものは、共通の規則の「ワークスペース」に従う
  - 所属なし: どのワークスペースにも所属しない人が開いたとき。所属するワークスペースが無いことを示す
- **シナリオ**: AUTH-02, AUTH-05

### P07 スクリプトの認証の承認

- **目的**: スクリプトの実行環境へ、自分に紐付くトークンを渡すことを承認する。
- **機能**:
  - 依頼の内容として、発行するトークンの許可と有効期限、確認用のコードを確認する
  - 自分が所属するワークスペースを一覧する。ワークスペースごとに、対象に選べるかどうかを示す。選べるワークスペースから、対象のワークスペースを選ぶ
  - 承認する、または承認しない
  - 多要素認証の設定が必要なワークスペースから、P05 を開く。設定を終えると、この画面へ戻る
- **状態**:
  - ログインが必要: ログインしていないとき。P01 を経て戻る
  - 承認待ち: 承認用の URL を開いたとき
  - 選べないワークスペース: 多要素認証が必須で未設定のワークスペースと、そこで持つ権限が依頼の許可に足りないワークスペース。前者には設定が必要なことを、後者には不足する権限を添えて示す。依頼は残り、ほかのワークスペースを選べる
  - 選べるワークスペースが無い: 所属するすべてのワークスペースが選べないとき。承認できないことを示す
  - 所属なし: どのワークスペースにも所属しないとき。承認できないことを示す
  - コードの期限切れ: 確認用のコードの期限が過ぎているとき
  - 拒否: 選べると示した後、承認の確定までに権限が縮小されて、依頼の許可に足りなくなったとき。トークンを発行せず、不足する権限を示す
  - 承認済み: 承認したとき、承認済みの依頼の承認用の URL を開いたとき。トークンの値を示さない。示す依頼の内容は、AUTH-06 の「承認済みの依頼の内容の確認」に従う
  - 承認しなかった: 承認しないことを選んだとき
- **シナリオ**: AUTH-06

## コンテンツ

### P08 コンテンツ一覧

- **目的**: 一つのモデルのコンテンツを見つけ、複数のコンテンツをまとめて扱う。
- **機能**:
  - 通常の管理対象のコンテンツを、最新の内容で一覧する。一覧表示用の項目の値、公開状態、下書きの有無、作成日時、更新日時を示す。一覧表示用の項目が未設定のコンテンツは、コンテンツID で示す

  - コンテンツを複製する

  - 確認の中で、ほかのモデルのコンテンツを検索して対象に加える、対象から外す。完全削除では、ごみ箱のコンテンツも一件ずつ加えられる。エラーで示された参照先と参照元は、その場で対象に加えられる
  - 完全削除の確認の中で、削除を妨げている履歴の版を、一件ずつ対象に加える、対象から外す。対象に加えた版には、P10 の版の削除の確認と同じ内容を示す

- **状態**:
  - 一覧: コンテンツがあるとき
  - 選択中: コンテンツを選んだとき。選んだ対象に行える操作を示す
  - 公開できない、公開を取り消せない: P09 の同じ状態と同じ内容を、該当する対象ごとに示す
  - 非推奨のモデル: モデルが非推奨のとき。非推奨と示す
  - モデルが無い: モデルが無いワークスペースで、最初の画面として開いたとき。コンテンツを扱うモデルが無いことを示す。反映済みのスキーマの有無は示さない

### P09 コンテンツ編集

- **目的**: 一件のコンテンツの内容を確認・編集し、公開状態を変える。
- **機能**:
  - 最新の内容を、項目の型に応じた入力で示す。項目ごとに、表示名称、説明、入力例、必須条件、制約を示す
  - 公開状態、下書きの有無、保存状況、同じコンテンツを開いているほかのメンバーを示す
  - 入力を下書きとして保存する。入力エラーがあっても保存する。保存は、この画面で入力したメンバーの操作として行う
  - 本文を、入力した見た目のまま編集する。リンクは外部の URL とコンテンツへのリンクを選び分ける。コンテンツへのリンクは、参照先と同じ方法で選び、リンク先の一覧表示用の項目の値、公開状態、下書きの有無を示す
  - 貼り付けで取り込めない要素は、削除・変更する内容を示す。続けるか、貼り付けをやめるかを選ぶ。やめると、本文は貼り付けの前の状態を保つ
  - 繰り返しの要素とブロックを追加・削除・並べ替える。追加・削除・並べ替えは、保存するまで元に戻せる
  - コンテンツ参照の参照先を検索して選ぶ。候補ごとに、モデル、一覧表示用の項目の値、公開状態、下書きの有無を示す。選んだ参照先ごとに、一覧表示用の項目の値、公開状態、下書きの有無を示す。複数の参照先は、順序を入れ替え、外せる。候補が無い場合は、該当が無いことを示す
  - 登録済みのメディアを検索して選ぶ。候補ごとに、縮小した表示、管理用の名称、形式、画像の幅・高さ、公開範囲を示す。本文の画像では、画像でないメディアを、選べない候補として、理由とともに示す
  - ファイルのドロップと貼り付けでメディアを登録して挿入する。本文は画像のファイルだけを受け付ける。登録できないファイルには、理由、対応形式、容量の上限を示す
  - メディアの使用箇所ごとの説明を入力する。メディアの共有する説明を取り込む。共有する説明が未設定のメディアでは、取り込める説明が無いことを示す。メディアを付け替えても、使用箇所の説明は残る
  - 入力エラー、現行の制約を満たさない公開内容、参照切れ、一意な値の重複を、項目と理由で示す。参照切れの示し方は、`spec/scenario/content-editing.md` の「共通の規則」に従う。一意な値の重複は、相手のコンテンツを示す。公開内容に任意の参照として残る参照切れには、取得で未設定として返すことを示す。現行の制約を満たさない公開内容には、その公開内容を配信し続けていることを示す
  - 非推奨の項目は、非推奨と示し、値を読み取り専用にする。値の書き換えで変えることを示す。非推奨の選択肢は、非推奨と示し、新たに選べない。選んでいる値は、非推奨でない選択肢へ変えられる。非推奨の種類のブロックは、追加の候補に示さない。既存のブロックは、中の値を読み取り専用にし、削除できる
  - 公開中のコンテンツで、保存しても配信が変わらないことを示す。下書きと公開内容の差分を示す
  - 下書きを破棄する。破棄する変更を確認で示す。未保存の入力がある場合は、その入力も失うことを、あわせて示す
  - 保存が競合した場合、自分の入力と最新の内容の差分を項目ごとに示し、どちらを残すかを選んで保存し直す。自分の入力をすべて捨てて、最新の内容を読み込み直すこともできる。その場合は、入力を失うことを確認する
  - 表示アプリでプレビューを開く。未保存の入力がある場合は、入力を下書きとして保存してから開く。開けない場合は理由を示す
  - 公開する。未保存の入力がある場合は、入力を下書きとして保存してから、確認を示す。確認は、公開する内容または公開内容との差分、新たに公開するメディア、参照元への影響、一意な値が変わる場合の変更前後の値を示す。確認でやめても、確認の前に保存した下書きは残る
  - 公開を取り消す。公開取得で返さなくなること、内容が下書きとして残ること、任意の参照だけで参照している公開中の参照元、下書きから参照しているコンテンツ、使用しているメディアが公開のまま残ることを確認で示す
  - ごみ箱へ移動する。復元できること、自動整理で完全削除される時期、このコンテンツを下書きから参照しているコンテンツを確認で示す。未保存の入力がある場合は、その入力がごみ箱の内容に含まれないことを、公開中のコンテンツでは、公開取り消しを含むことと公開取り消しの確認の内容を、あわせて示す。非推奨のモデルのコンテンツでは、復元できることの代わりに、通常の管理対象へ戻せないことを示す
  - 公開、公開取り消し、ごみ箱への移動の確認の中で、エラーで示された参照先と参照元を、その場で対象に加える。加えた後は、複数のコンテンツの操作の確認（P08 と同じ内容）になる
  - 複製する。未保存の入力がある場合は、その入力を複製に含めないことを示す
  - 単一モデルのコンテンツを完全削除する。確認の内容と、確認の中で対象を加える操作は、P11 と同じ
  - P10 を開く
- **状態**:
  - 新規: 新規作成または複製を始めたとき。初期値を入れた入力を示す。最初の保存でコンテンツを作る。複製では、未設定にした一意な項目を入力が必要な項目として示す
  - 保存済み: コンテンツを開いたとき、保存が成功したとき
  - 未保存の入力がある: 項目の値を変えたとき
  - 保存中: 保存を始めたとき
  - 保存に失敗: 保存が拒否された、または失敗したとき。編集中のスキーマの変更では、現行スキーマに合わない項目と理由を示し、保持した入力を示したまま、現行スキーマの入力へ読み込み直す操作を示す。読み込み直した後の扱いは、EDIT-03 の「編集中のスキーマの変更」に従う。編集中に非推奨になった項目には、保存済みの値に戻す操作を示す。再ログインの後の保存の扱いは、EDIT-11 に従う
  - 競合: 編集を始めた後に、ほかの操作で最新の内容が変わっていたとき。変えた操作の種類、実行者、日時を示す。単一モデルの最初の保存の前に、ほかのメンバーがコンテンツを作っていたときを含む。その場合は、既にあることと、先に作られたコンテンツとの差分を示す
  - 公開できない: 入力エラー、一意な値の重複、公開されていない参照先があるとき。該当する項目と、重複の相手または参照先を示す
  - 公開を取り消せない: 公開を続けるコンテンツから、必須の参照または本文のリンクで参照されているとき。該当する対象、参照元、項目、解消方法を示す。公開中のコンテンツのごみ箱への移動でも同じ
  - 公開・プレビューを始められない: 公開またはプレビューを始めたときの未保存の入力の保存が、競合または失敗したとき。保存に失敗または競合の状態になる
  - 読み取り専用: 非推奨のモデルのコンテンツを開いたとき
  - ごみ箱へ移動済み: ごみ箱への移動を確定したとき。複数件を持つモデルのコンテンツでは P08 へ移る。単一モデルのコンテンツでは「内容が無い」状態になる
  - 内容が無い: 単一モデルが、通常の管理対象にコンテンツを持たないとき。初期値を入れた入力を示す。編集権限を持たないメンバーと、非推奨の単一モデルでは、入力を示さず、内容が無いことを示す（EDIT-04）
  - ごみ箱にある: 開いたコンテンツが、開くまでの間にごみ箱へ移動されていたとき。ごみ箱にあることと、一覧へ戻る操作を示す
- **シナリオ**: EDIT-02, EDIT-03, EDIT-04, EDIT-05, EDIT-06, EDIT-07, EDIT-08, EDIT-09, EDIT-10, EDIT-11, EDIT-12, EDIT-14, EDIT-15, EDIT-16, PUB-01, PUB-03, PUB-05, PUB-07, MEDIA-02, MEDIA-03, MEDIA-05, MEDIA-09, SDEV-04


この画面は通常の管理対象のコンテンツを扱う。ごみ箱のコンテンツは P11 が扱う。単一モデルのコンテンツの完全削除を確定すると、「内容が無い」状態になる。

### P10 コンテンツ履歴

- **目的**: 一件のコンテンツの過去の版を確かめ、取り戻し、削除する。
- **機能**:
  - 版を新しい順に一覧する。版ごとに、その内容を置き換えた、またはなくした操作の種類、実行者、日時、公開内容だった版か下書きだった版かを示す。実行者の示し方は、EDIT-13 の手順 3 に従う
  - 移行で変換された内容を、EDIT-13 の手順 4 のとおりに示す
  - 版の内容を、現行スキーマの形で確認する。その内容を作った操作の種類、実行者、日時を示す。移行前の保存内容を再現しないことを示す
  - 二つの版、版と最新の内容、版と現在の公開内容の差分を項目ごとに比較する
  - 版を下書きとして復元する。最新の内容との差分、下書きが置き換わること、公開内容と配信が変わらないこと、非推奨の対象の値を復元しないことを確認で示す
  - 版を一つまたは複数選んで削除する。対象の版ごとの操作の種類、実行者、日時、公開内容だった版か下書きだった版か、コンテンツの公開内容、下書き、ほかの版は変わらないこと、対象の版が使用するメディアと参照するコンテンツ、削除の後に残る使用・参照を確認で示す
  - 保持方針より古い版が整理されることを示す
  - そのコンテンツの P09 へ戻る。ごみ箱のコンテンツでは、そのコンテンツを選んだ P11 へ戻る
- **状態**:
  - 一覧: 版があるとき
  - 版の内容: 版を選んだとき
  - 比較: 二つの版、または版と現在の内容を選んだとき
  - 復元済み: 版の復元を確定したとき。P09 へ移り、復元した下書きを示す
- **シナリオ**: EDIT-13, EDIT-14, EDIT-17, PUB-06

ごみ箱のコンテンツの履歴は、版の確認、比較、削除を扱う。ごみ箱のコンテンツの復元と完全削除は、P11 が扱う。

### P11 ごみ箱

- **目的**: ごみ箱のコンテンツを確かめ、復元または完全削除する。
- **機能**:
  - ごみ箱のコンテンツを一覧する。モデル、一覧表示用の項目の値、移動した日時と実行者、自動整理で完全削除される時期を示す
  - モデルで絞り込む
  - コンテンツを選んで、この画面で内容（下書き）を読み取り専用で確認する。ごみ箱にある間に移行または値の書き換えで変わった内容は、変わった後の内容を示す。P10 で履歴を確認する
  - コンテンツを復元する。復元は、確認を挟まずに確定する。未公開として戻したことと、公開していないことを、結果で示す
  - 一件以上のコンテンツを完全削除する。履歴を含めて削除し復元できないこと、公開中の対象では公開取り消しを含むこと、任意の参照だけで参照している参照元で参照が未設定になること、使用しているメディアとほかのコンテンツは削除しないこと、バックアップに残り得ることを CMS の通常データと区別して、確認で示す。対象を変えるたびに、すべての対象の削除条件を確かめ直して示し直す
  - 確認の中で、ほかのモデルのコンテンツと、通常の管理対象のコンテンツを検索して、一件ずつ対象に加える、対象から外す。エラーで示された参照元は、その場で対象に加えられる
  - 完全削除の確認の中で、削除を妨げている履歴の版を、一件ずつ対象に加える、対象から外す。対象に加えた版には、P10 の版の削除の確認と同じ内容を示す
- **状態**:
  - 一覧: ごみ箱にコンテンツがあるとき
  - 内容: ごみ箱のコンテンツを選んだとき。内容と、そのコンテンツに行える操作を示す
  - 復元済み: 復元したとき。P09 へ移り、復元した下書きの入力エラー、参照切れ、一意な値の重複を示す
  - 削除できない: 削除の後に残る対象から必要な参照があるとき。該当する対象、参照元、参照している内容の種類（公開内容、下書き、履歴の版）、参照元の置き場所（通常、ごみ箱）、解消方法を示す
- **シナリオ**: EDIT-01, PUB-06, PUB-07

- **機能**:

  - 派生形式の生成状況で絞り込む

  - 一覧: メディアがあるとき
  - 登録中: ファイルを送信しているとき。やめるとメディアは登録されない
  - 登録済み: 登録が終わったとき。非公開のメディアとして一覧に加わる
- **シナリオ**: MEDIA-01, MEDIA-03, MEDIA-10

### P13 メディア詳細

- **目的**: 一件のメディアの説明、使用箇所、公開範囲、派生形式を扱う。
- **機能**:
  - 形式、容量、画像の幅・高さ、公開範囲を確認する
  - 管理用の名称、検索情報、共有する説明（代替テキスト、キャプション）を編集する。共有する説明の変更が、既存の使用箇所と公開表示を書き換えないことを示す
  - 使用箇所を一覧する。使用箇所は、メディアを使っている内容ごとに一件で、コンテンツ、モデル、内容の種類（公開内容、下書き、履歴の版）、コンテンツの置き場所（通常、ごみ箱）、その内容の中の項目の位置を示す。位置が複数あれば、一件の中に並べて示す。公開使用の有無を示す
  - 使用箇所から、そのコンテンツの P09 へ移る。置き場所がごみ箱の使用箇所からは、そのコンテンツを選んだ P11 へ移る
  - 公開のメディアを非公開化する。CMS が管理する配信で、資格（メンバーのセッション、またはプレビュー用の配信先）を示さない要求による、元の画像と派生形式の新しい取得を拒否することと、表示アプリ、その CDN、ブラウザが保持した内容と外部が保存・複製した内容を回収できず、保持の期限まで表示され得ることを、確認で示す。公開使用があるメディアでは、確認で公開使用の使用箇所を示し、確定しない
  - メディアを削除する。完全削除であること、派生形式も削除すること、公開のメディアでは配信が止まることと、表示アプリ、その CDN、ブラウザが保持した内容と外部が保存・複製した内容を回収できないことを、確認で示す
  - 削除の確認の中で、削除を妨げている履歴の版を、一件ずつ対象に加える、対象から外す。対象に加えた版は、メディアと同時に削除する。対象に加えた版には、P10 の版の削除の確認と同じ内容を示す
  - 派生形式ごとの生成状況と、生成済みの画像形式、幅、高さを確認する。失敗した派生形式の生成をやり直す
- **状態**:
  - 表示: メディアを開いたとき
  - 未保存の入力がある: 名称、検索情報、共有する説明を変えたとき
  - 削除できない: 対象に加えた履歴の版のほかに使用箇所があるとき。使用箇所と、内容の種類と置き場所ごとの解消方法と必要な権限を示す
  - 使用箇所なし: 使用箇所が無いとき
  - 派生形式の生成中・失敗: 派生形式が生成中または失敗のとき。失敗の理由を示す
- **シナリオ**: MEDIA-04, MEDIA-06, MEDIA-07, MEDIA-08, MEDIA-09, MEDIA-10


## フォーム

フォームごとの運用設定（通知先、通知定義、受付状態、回答の保持方針）は、フォームごとの 1 画面（P15）で扱い、メンバーが持つ権限に応じて出し分ける。送信接続設定はワークスペースに一つで、通知設定の権限を持つメンバーの画面（P16）が扱う。

回答と通知は、回答の一覧と詳細（P17、P18）の 1 組で扱う。権限ごとに示す内容は `spec/scenario/form-operation.md` の「共通の規則」に、示す操作は共通の規則の「権限」に従う。


### P14 フォーム一覧

- **目的**: フォームごとの通知と受付の状況と、紐付けを待つ運用設定を把握し、設定するフォームを選ぶ。
- **機能**:
  - 現行のフォームを一覧する
  - 回答が残る削除済みフォームを、現行のフォームと区別して示す（FORM-11）。受付状態の代わりに、受付が終了していることを示す
  - メンバーが持つ権限に応じて、次の列を示す

    | 権限 | フォームごとに示すもの | 紐付けを待つ運用設定 |
    | --- | --- | --- |
    | 通知設定の権限 | 通知定義の参照の不整合の有無 | 通知先、通知定義 |
    | 受付管理の権限 | 受付中か受付停止か | 受付状態、回答の保持方針 |

  - フォームを選んで P15 を開く
  - 紐付けを待つ運用設定を、対象のキー、運用設定の種類と内容とともに示す
- **状態**:
  - 一覧: フォームまたは削除済みフォームがあるとき
  - 紐付け待ちあり: 紐付けを待つ運用設定があるとき。スキーマにないキーのものも、待つ状態のまま示す
- **シナリオ**: FORM-02, FORM-03, FORM-04, FORM-05, FORM-06, FORM-11, HOST-03, SMIG-13

削除済みフォームの P15 への入口は、通知設定の権限を持つメンバーにだけ示す。

### P15 フォームの設定

- **目的**: 一つのフォームの運用設定を決め、受付を始める、止める。
- **機能**:
  - メンバーが持つ権限に応じて、次の内容と操作を示す

    | 権限 | 示す内容 | 操作 |
    | --- | --- | --- |
    | 通知設定の権限 | 通知先ごとのメールアドレスと有効・無効、通知定義、参照の不整合 | 通知先の管理、通知定義の編集 |
    | 受付管理の権限 | 受付状態、回答の保持方針、有効な通知先の件数、送信接続設定の登録の有無、通知定義の参照の不整合の有無 | 受付の有効化と停止、保持方針の変更と既存の回答への適用 |

  - 通知先を追加、修正、有効化、無効化、削除する
  - 通知定義の件名、本文、送信者の表示名、返信先を編集する
  - 件名と本文に、現行のフォームの項目から選んで参照を入れる。回答の項目の値、全項目の一覧、未入力の項目の出し分け、問い合わせ対象の送信時の情報、受付日時を選べる
  - 返信先を、メールアドレス形式の項目から選ぶ、または指定しない。項目の値が形式の検証だけを経ていて、連絡先の所有と到達を保証しないことを示す
  - 不整合のある参照を、参照するキーと理由とともに示す。現行の項目へ選び直す、または取り除く
  - 入力例による表示を確認する。入力例を当てはめた件名、本文、返信先を示す。入力例を持たない項目は未入力として示す
  - 通知定義を保存する。保存後に受け付ける送信に適用し、受付済みの回答の通知と手動再試行は受付時の通知定義のままであることを示す
  - 受付を有効にする。有効な通知先の件数、送信接続設定の登録の有無、回答の保持方針、通知定義の参照の不整合の有無を確認で示す
  - 受付を停止する。以後の送信が受付失敗になることと、保存済みの回答と未送信の通知を取り消さないことを確認で示す
  - 回答の保持方針を変更する。適用される回答の範囲、自動整理で復元できなくなること、削除した回答からは通知も手動再試行も行えないこと、バックアップと、メール送信環境や受信箱に残る情報が保持方針の対象でないことを示す。既存の回答にも適用するかを選べ、選んだ場合は、同じ確認で次の機能の確認の内容を示す
  - 現在の保持方針を既存の回答へ適用する。適用範囲の件数と受付期間、保持期限が変わる件数、次の自動整理で削除する件数を確認で示す
  - 送信接続設定が未登録の場合、P16 を開く。P16 で保存すると、このフォームの P15 へ戻る
  - P18 から開いた場合、通知先を保存した後に、元の P18 へ戻る
- **状態**:
  - 表示: フォームを開いたとき
  - 未保存の入力がある: 通知先、通知定義、保持方針を変えたとき
  - 不整合あり: 通知定義に参照の不整合が残っているとき
  - 有効にできない: 有効な通知先がゼロ、または送信接続設定が未登録のとき。足りない設定を示す。通知設定の権限を持たないメンバーには、通知設定の権限を持つメンバーへ依頼することを示す
  - 受付状態の確定: 受付の有効化・停止を確定したとき。確定の前にほかのメンバーが同じ受付状態へ変えていた場合も区別せず、確定の結果の受付状態を示す
  - 保持方針の適用の中止: 既存の回答への適用の途中で、保持方針が変わったとき。適用を止めたことと、保持方針が変わったことを示す。確認を、現在の保持方針で示し直す
  - 削除済みフォーム: スキーマの反映で削除されたフォームを開いたとき、操作の前にフォームが削除されたとき。受付が終了していることを示す。通知先の管理だけを示し、通知定義の編集、受付状態、保持方針を示さない
- **シナリオ**: FORM-02, FORM-03, FORM-04, FORM-05, FORM-06, FORM-11, SMIG-13


### P16 送信接続設定

- **目的**: ワークスペースの通知メールを送れる状態にする。
- **機能**:
  - 接続先、認証情報、接続条件を登録・更新する。接続条件は、送信者のアドレスを含む。認証情報を入力せずに更新すると、登録済みの認証情報を使い続けることを示す
  - 試験メールの宛先を指定して、入力中の設定で動作確認を行う。受理が受信箱への到着を意味しないことと、送った試験メールを取り消せないことを示す
  - 更新を保存する。影響するフォームを確認で示す
  - P15 または P18 から開いた場合、保存の後に、元の画面へ戻る
- **状態**:
  - 未登録: 設定が無いとき
  - 登録済み: 設定があるとき
  - 未保存の入力がある: 入力を変えたとき
  - 動作確認の結果: 動作確認を行ったとき。受理されたか、失敗した理由を示す。結果は保存の条件にならない
- **シナリオ**: FORM-01

### P17 回答一覧

- **目的**: 保存した回答と、回答ごとの通知の送信結果を見つけ、複数の回答をまとめて扱う。
- **機能**:
  - 回答を受付日時の新しい順に一覧する。受付日時とフォームを示す
  - フォームと受付期間で絞り込む。フォームの選択肢は、回答が残る削除済みフォームを、現行のフォームと区別して含む（FORM-11）
  - 一覧表示用の項目の値を示し、一覧表示用の項目で検索する（FORM-07）
  - 回答ごとの通知の送信結果と、送信失敗の通知の未対処・対処済みを示す
  - 送信結果、未対処・対処済みで絞り込む（FORM-09）
  - 回答を選んで P18 を開く
  - 一件以上の回答を選んで、一度に削除する。選んだ件数、復元できないこと、未送信の通知と手動再試行を開始しないこと、送信中・受理済みの通知を取り消せないこと、バックアップと、メール送信環境や受信箱に残る情報は消えないことを確認で示す。確定までに既に無くなっていた回答は、削除済みとして扱う
  - 送信失敗の通知を持つ回答を一件以上選んで、一度に通知を再試行する。通知ごとの再試行の宛先、受付時の通知対象から外れた宛先と加わった宛先、重複して届き得ること、宛先が残らない通知を確認で示す。確認の中で、宛先が残らない通知を対象から外す。再試行は、確認で示した時点の通知を対象にする
  - 送信失敗の通知を持つ回答を一件以上選んで、一度に通知を対処済みとして記録する。確認は、取り消せないことと、対処済みの記録の扱い（`spec/scenario/index.md` の「未対処の失敗」）を示す
- **状態**:
  - 一覧: 回答があるとき
  - 選択中: 回答を選んだとき。選んだ対象に行える操作を示す
  - 再試行の結果: 再試行が終わったとき。通知ごとの結果を示す
- **シナリオ**: FORM-07, FORM-08, FORM-09, FORM-10, FORM-11

内容と操作の出し分けは、この章の冒頭に従う。送信結果、未送信の内訳、対処済みの記録、先に始まった再試行の扱いは、`spec/scenario/index.md` の「未対処の失敗」に従う。再試行と対処済みの記録に選べる通知は FORM-09 と FORM-10 に、一覧に現れる回答は FORM-09 に従う。

### P18 回答詳細

- **目的**: 一件の回答の送信時の内容と、通知の宛先ごとの結果を確かめ、対処する。
- **機能**:
  - 受付日時とフォームを確認する
  - 受付時の項目、表示名称、選択肢、入力内容を確認する。連絡先の項目には、形式の検証だけを経た値で、連絡先の所有と到達を保証しないことを示す
  - 問い合わせ対象の送信時の情報を確認する。現在のコンテンツがある場合は、送信時の情報と区別してリンクを示す。リンクは、そのコンテンツの P09 を開く。ごみ箱にあるコンテンツでは、そのコンテンツを選んだ P11 を開く
  - 回答を削除する。確認の内容は P17 と同じ
  - 通知の送信結果と、宛先ごとに、メール送信基盤の受理を確認できたかどうか、失敗の理由、必要な対処を確認する。送信失敗が未着を意味しないことを示す
  - 送信に失敗した通知を再試行する。再試行の宛先、受付時の通知対象から外れた宛先と加わった宛先、重複して届き得ることを確認で示す。再試行は、確認で示した時点の通知を対象にする
  - 送信失敗の通知を対処済みとして記録する。確認の内容は P17 と同じ。複数の通知を一度に記録する操作は P17 が持つ
  - 対処のために、そのフォームの P15 と、P16 を開く
- **状態**:
  - 表示: 回答を開いたとき
  - 削除済み: 削除を確定したとき。P17 へ戻る
  - 未送信: 再試行を確定したとき。通知を未送信として示す
  - 再試行の結果: 再試行が終わったとき。宛先ごとの結果と理由を示す
- **シナリオ**: FORM-07, FORM-08, FORM-09, FORM-10, FORM-11

内容と操作の出し分けは、この章の冒頭に従う。送信結果、対処済みの記録、先に始まった再試行の扱いは、`spec/scenario/index.md` の「未対処の失敗」に従う。

## ワークスペースの管理

### P19 メンバー

- **目的**: ワークスペースを利用できる人と、その権限を管理する。
- **機能**:
  - メンバーを一覧する。役割、権限、所有者であるかどうか、多要素認証の設定の有無を示す
  - メールアドレスと権限を決めて招待する。権限は、標準の役割（管理者、編集者、閲覧者）または個別の組み合わせで決める
  - 未使用の招待を、対象、権限、有効期限とともに一覧する。有効期限を過ぎた招待は、期限切れと示す。招待を取り消す。ホスティング運営者が発行した初期所有者の招待（HOST-04）は、一覧に示さず、取り消しの対象にしない
  - 未使用の招待があるメールアドレスへ招待し直す。期限内の招待も、期限切れの招待も、新しい招待に置き換わる。置き換えは、`spec/scenario/workspace-admin.md` の「共通の規則」の「招待の種類」に従う
  - 外部メールを使えない設置では、招待の確定時にだけ、一度だけ使える招待の URL を示す。メンバーは、招待する本人を確かめて、URL を CMS の外で渡す
  - メンバーの権限を変更する
  - 通知設定の権限を与えるとき、回答の入力内容を通知経由で取得できることを示す
  - メンバーの利用を解除する。確認の内容は WS-03 に従う
  - 所有者を変更する。新しい所有者がすべての権限を持つこと、新しい所有者が通知設定の権限を新たに持つ場合は回答の入力内容を通知経由で取得できること、元の所有者が管理者の役割を持つメンバーになること、元の所有者が自分で戻せないことを確認で示す
  - 多要素認証を必須にする。未設定のメンバーと、設定を終えるまでそのメンバーが利用できなくなることを確認で示す
  - 多要素認証の必須を解除する
- **状態**:
  - 一覧: 画面を開いたとき
  - 招待の入力: 招待を始めたとき
  - 未保存の入力がある: メンバーの権限を変えたとき。保存するまで権限は変わらない
  - 所有者がいない: 所有者がいないワークスペースのとき。所有者がいないことと、ホスティング運営者へ初期所有者の招待の発行し直しを依頼することを示す
  - 招待済み: 招待を確定したとき。有効期限を示す。未使用で期限内の招待を置き換えた場合は、前の招待が失効したことを示す
  - 招待の送信に失敗: 招待のメールを送れなかったとき。招待を残し、送信に失敗したことを示す
- **シナリオ**: WS-01, WS-02, WS-03, WS-04, WS-05


### P20 トークン一覧

- **目的**: 発行済みのトークンを見直し、失効させ、ブラウザ用トークンの利用元の限定と利用量の制限を変える。
- **機能**:
  - トークンを一覧する。示す項目は、WS-07 の「一覧して見直す」の手順 1 に従う
  - メンバーに紐付くトークンを、手動発行したトークンと初期構成で宣言したトークンと区別して示す
  - 有効期限が近い、発行者または紐付くメンバーが解除された、長く使われていないトークンに絞り込む
  - ブラウザ用トークンの値を確認する
  - トークンを失効させる。次の要求から拒否すること、使うアプリが止まること、取り消せないことを確認で示す
  - ブラウザ用トークンの利用元の限定と利用量の制限を変更する。利用元の限定が本人確認にならないことを示す
  - 範囲の紐付けを待つトークンを、トークンの名称と、紐付けを待つキーとともに示す。トークンの値を示さない
  - P21 を開く
- **状態**:
  - 一覧: トークンがあるとき
  - 紐付け待ちあり: 範囲の紐付けを待つトークンがあるとき
  - 未保存の入力がある: 利用元の限定または利用量の制限を変えたとき
- **シナリオ**: WS-06, WS-07, HOST-03

一覧に載る範囲、期限切れと範囲が空のトークンの示し方は、WS-07 に従う。発行の後に変更できない項目を変える場合は、P21 で新しいトークンを発行して入れ替える。

### P21 トークンの発行

- **目的**: アプリに渡すトークンを、許可を決めて発行する。
- **機能**:
  - 名称、種類（サーバー用、ブラウザ用）、許可、範囲、有効期限を決める。範囲は、ワークスペース全体、または選んだモデル・フォームの集合から選ぶ。選択肢として、現行スキーマのモデルとフォームを、キーと表示名称で示す。スキーマ反映の許可を選んだ場合は、ワークスペース全体だけを選べる
  - 種類とメンバー自身の権限から、選べる許可だけを示す。コンテンツ管理の許可では、トークンに許可する操作を示す
  - ブラウザ用では、利用元の限定と利用量の制限を設定する。値が第三者に知られる前提であることと、利用元の限定が本人確認にならないことを示す
  - 有効期限を設けない場合は、期限なしを明示して選ぶ
  - 発行の後に変更できない項目を示す
  - 発行して、トークンの値を受け取る
- **状態**:
  - 入力: 画面を開いたとき
  - 発行済み: 発行を確定したとき。トークンの値を示す。サーバー用では、値をこの時だけ示し、後から表示できないことを示す
- **シナリオ**: WS-06

### P22 プレビュー先の設定

- **目的**: 編集画面からのプレビューを開く表示アプリを決める。
- **機能**:
  - プレビュー先の表示アプリの URL を設定する、取り除く。プレビューを開くたびに、トークンへ引き換える値をこの URL へ渡すことを入力欄で示す
- **状態**:
  - 未設定: URL が無いとき
  - 設定済み: URL があるとき
  - 未保存の入力がある: 入力を変えたとき
- **シナリオ**: WS-08

### P23 表示アプリへの通知設定

- **目的**: 公開内容の変更の通知の宛先を決める。
- **機能**:
  - 登録済みの宛先を一覧する
  - 通知の宛先と秘密情報を登録する
  - 宛先を変更する、秘密情報を置き換える、宛先を削除する
  - P28 を開く
- **状態**:
  - 一覧: 宛先があるとき
  - 宛先が無い: 宛先が一つも無いとき。通知を送らないことを示す
  - 未保存の入力がある: 宛先の入力を変えたとき
- **シナリオ**: WS-09

### P28 表示アプリへの通知の状況

- **目的**: 公開内容の変更の通知が伝わったかを確かめ、伝わっていない通知を送り直す。
- **機能**:
  - 通知と宛先の組を、通知の新しい順に一覧する。組ごとに、通知の内容（通知の種別と確定した日時、変更した対象のコンテンツ、スキーマの版、参照元への影響）、宛先、送信結果、送信した日時、失敗の理由を示す。通知の種別は、PUB-08 の手順 2 に従う。一つの操作で確定した複数の変更は、変更したすべての対象を列挙した一つの通知である。送信失敗の組には、未対処か対処済みかを示す
  - 届かなかった通知を自動で再試行することを示す
  - 一覧を、未対処と対処済みで絞り込む
  - 送信成功が、宛先による通知の受け取りを示し、表示反映を示さないことを示す
  - 送信失敗の組を一件以上選んで、一度に再試行する
  - 送信失敗の組を一件以上選んで、一度に対処済みとして記録する。確認は、取り消せないことと、対処済みの記録の扱い（`spec/scenario/index.md` の「未対処の失敗」）を示す
  - 宛先の設定を直すために、P23 を開く
- **状態**:
  - 一覧: 通知と宛先の組があるとき
  - 宛先が無い: 宛先が一つも無いとき。通知を送らないことを示す
  - 選択中: 送信失敗の組を選んだとき
  - 再試行の結果: 再試行が終わったとき。組ごとの結果を示す。再び送信失敗になった組には、新しい理由を示す
- **シナリオ**: PUB-08

送信結果、未対処と対処済み、自動の再試行、手動再試行の送り方、再試行が先に始まっていた組の扱いは、`spec/scenario/index.md` の「未対処の失敗」に従う。再試行と対処済みの記録に選べる組、宛先が削除されている組と対象のコンテンツが完全削除されている通知の示し方は、PUB-08 の異常系に従う。

### P24 コンテンツの保持方針

- **目的**: 履歴とごみ箱を保持する期間を決める。
- **機能**:
  - 履歴の保持方針と、ごみ箱の保持方針を確認する
  - 保持方針を変更する。新たに整理対象になる版とコンテンツの件数、復元できなくなる条件、バックアップが対象でないことを確認で示す
- **状態**:
  - 表示: 画面を開いたとき
  - 未保存の入力がある: 入力を変えたとき
- **シナリオ**: WS-10

### P25 操作履歴

- **目的**: 設定とスキーマを、誰がいつ変えたかを追う。
- **機能**:
  - 記録を日時の新しい順に一覧する。日時、実行者、操作の種類、対象を示す。実行者の示し方は、WS-11 の手順 1 に従う
  - 期間、操作の種類、実行者で絞り込む
  - 記録を開いて、変更の内容を確認する
- **状態**:
  - 一覧: 記録があるとき
  - 記録の内容: 記録を開いたとき。対象が現在は無い場合、そのことを示す
- **シナリオ**: WS-11

  - P27 を開く

  - スキーマが未反映: 一度も反映していないとき

### P27 反映の記録

- **目的**: スキーマの版の記録と、反映の進行状況・結果を確かめる。
- **機能**:

  - 適用中の反映を確認する。反映ごとの結果の一覧と別に示す
  - 反映ごとの結果の一覧を確認する。一覧は、終えた反映（成功と失敗）を示し、適用中の反映を含めない。どちらも、適用状況の確認のコマンドの出力と同じ内容を示す
  - 結果に示されたコンテンツの P09 を開く
- **状態**:
  - 一覧: 版の記録があるとき
  - 記録が無い: 一度も反映していないとき
  - 適用中: 反映が適用中のとき。成功として示さない
  - 反映ごとの結果: 終えた反映があるとき。反映ごとに、成功または失敗と、理由と対象を示す
- **シナリオ**: SDEV-07, SMIG-14
